# 代代守村：条件提示、玩法说明与警钟调整方案

后续配置 10 更新：资源栏已统一为单行“粮 80/200、木 60/200、人 6/8”，不显示“上限”文字；起步章补充每日口粮，家庭条件改在状态卡内展示。以 [18 村庄视觉与每日口粮](18_村庄视觉与每日口粮.md) 为当前实现，本文保留配置 9 的实施记录。

日期：2026-11-11。状态：独立可行性审核已通过，用户已确认整套方案与警钟 15 个战斗秒。已实施为配置 9，延续配置 8 的自动驻塔和异版重开修复。

## 1. 目标与范围

用户要求梳理全部操作条件，让玩家知道为何不能操作；警钟持续更久、效果更显眼；在小记添加“玩法说明”按钮，打开带标签分类的说明面板；顶部资源栏加“粮、木、人”。

保留微信专用、竖屏、单手滑动、关闭按钮在右侧、现有羊皮纸与木色美术。除明确确认的警钟持续时间外，不改变生育、年龄、口粮、成本、人数、旅人和驻塔规则。说明内容直接依据当前源码，数值尽量引用规则常量。

## 2. 修改前核对的实现（配置 8）

- `VillageRules.birthUnavailableReason()` 与出生命令共用预检，但当前只返回首个阻塞原因；“双亲需仍在劳作期”“双亲需至少余 3 夜”不易理解。
- `canMarry()` 限定已成年未退休、异性、单身、非直系且非同胞；选择界面会过滤不合格对象，空列表未说明筛选原因。
- `Growth.upgradeUnavailableReason()` 校验白天、数值范围、仓储及资源；建设行已有费用，但“未满足”与不足原因不够具体。
- `GameView` 的建塔、改建、照料、旅人、珍藏等入口仍有部分条件只在点击后校验，或置灰后缺少原因。
- 警钟为每晚一次，`RULE.bellTicks=100`、固定步长 0.05 秒，已驻塔攻速乘 1.5，按战斗时间计时；当前无剩余时长或塔上生效反馈。
- 小记为 `GameView.drawPanel()` 的现有分支；现有 `modal()`、`button()`、`ScrollList`、`UiTheme` 可直接复用。
- 顶部三个资源卡当前为 212×74 逻辑像素，采用单行数字和 k/m/b/t/q 缩写；需要保持不换行。

## 3. 采用的界面方案

采用“操作处给即时原因，说明面板讲完整规则”。各类灰色条目保留，玩家不必点击失败才能知道条件。多项不满足时，列表按已有校验顺序显示首先需解决的原因；完整条件和操作办法可在对应说明标签查阅。

另一个可行方案是每个操作弹出完整条件清单；它会增加频繁点击和面板跳转，与本轮减少操作困惑、单手操作的目标不如前者一致，因此本方案不采用。未来若要家庭独立条件详情，可单独迭代。

### 3.1 条件覆盖与表达

| 场景 | 当前条件 | 玩家能看到的解释 |
| --- | --- | --- |
| 成家 | 成年、未退休、异性、单身，非直系与同胞 | 说明双方资格；没有对象时明确是哪类候选不足；无合格组合时入口置灰 |
| 迎接孩子 | 白天；父母均未退休且各剩至少 3 夜；有住房；没有未成年孩子；间隔 4 个成功守夜；有未在照料他人的照料者；20 粮 | 具体父母姓名与退休状态、剩余/要求夜数、还需等几夜、缺多少粮、住房人数等；保持原校验顺序 |
| 孩子成长 | 获得照料并成功守住 2 夜 | 显示“还需照料并守住 X 夜”；无人照料明确说明不会成长 |
| 生产和调岗 | 成年且未退休，岗位容量；满岗可替换 | 明确“距退休 X 夜”；工作已满时说明可换人或升级，不把可替换的岗位锁死 |
| 照料 | 成年未退休，目标为尚无照料者的孩子 | 无合适孩子时按钮置灰并说明；照料者仍可夜间驻塔 |
| 驻塔 | 已建塔，成年未退休，每人一塔 | 自动补人、人数不足、跨塔对调；白天工作不受影响 |
| 建造、改建与升级 | 白天、材料足够；升级费用不超过仓储 | 建塔/改建材料不足提前置灰；显示缺少的材料；仓储不足说明先修缮民居 |
| 民居与修门 | 民居最多 5 间、总人口 20；修门需门受损及木材 | 区分增建加住房、修缮加仓储；门完好和木材不足给出不同原因 |
| 旅人加入 | 有住房名额 | 满员时明确无法接纳，可谢绝后白天增建民居；不新增清晨建房行为 |
| 家谱珍藏 | 最多 20 位，已珍藏者仍可取消 | 上限时提示先取消一位；不禁止取消珍藏 |
| 守夜与警钟 | 可以缺粮/无人驻塔守夜；警钟需本夜战斗进行且未用过 | 缺粮会降攻速、空塔不攻击的警告；暂停时说明恢复后可敲钟，不制造不能推进的死路 |
| 好友榜与保存 | 首次成功守住一波后解锁；本地自动保存；异版需确认重开 | 在说明中解释解锁、失败波不计、重进夜战从本夜开头开始及无离线收益 |

文案使用“已退休”“距退休 X 夜”“还差 X”等具体词。列表中可用项正常颜色，不可用项置灰，材料不足仍突出红色。长条件必要时使用更高的条目容纳，不缩成难读小字或挤压按钮描边。错误提示与预检共享已有规则；新增复用函数仅限有明确业务意义的条件判断，不建设通用规则框架。

### 3.2 玩法说明

入口：小记 → 玩法说明。小记保留音乐与重新开村入口，减少与说明面板重复的零散提示。

说明面板顶部为标题及右侧关闭，下方一行 5 个标签，每个标签内上下滑动，切换标签回到该章开头：

| 标签 | 内容 |
| --- | --- |
| 起步 | 白天准备→守夜→清晨；粮/木/人数含义；口粮与仓储；保存、离线与重新开村；好友榜解锁与最高波数 |
| 村民 | 自动岗位、手动换岗、白天与夜间分配独立；劳作、退休、养老、寿终与家谱；旅人及精英 |
| 家庭 | 成家限制、迎接孩子全部条件、照料与两夜成年、4 夜间隔、天赋继承、性别调节与接班 |
| 建设 | 民居增建和修缮区别、农田/伐木场岗位与产量、城门加固与修复、持续升级与费用、仓储限制 |
| 守夜 | 自动驻塔与换人、三类塔和五类敌人、胜负条件、警钟、倍速、暂停、季节村规和年度挑战 |

正文左对齐，标题层级明确，使用现有墨色 `#48311f`、森林绿 `#557637`、木色 `#9a591f`、金色 `#d49a35`，保留正文描边。正文采用现有系统字体，约 28～30 逻辑像素，行距不拥挤；内容按实测高度布局，滚动到底完整可见。标签复用按钮整体按压，无外部网页、图片大底板或新字体。

在夜战中打开或切换说明沿用 `CHOICE` 暂停，关闭后只解除面板暂停，主动暂停、后台和保存冻结不被误解除。说明是纯查看，不写进度、不扣资源。

### 3.3 警钟（用户已选 15 个战斗秒）

用户选择将持续时间由 5 延长至 **15 个战斗秒** ，攻速仍提高 50%，每夜仍一次，不消耗材料。1/2/3 倍速对应约 15/7.5/5 现实秒，暂停停止倒计时。此改动会降低防守难度，实施后重新运行长期模拟。

生效期间显示“攻速 +50%”及剩余战斗秒数；已驻人塔出现克制的金色脉冲光圈，结束后关闭。效果随战斗计时暂停，不全屏闪烁；保持当前攻击冷却、缺粮叠加和夜战重放语义。使用 Laya 现有矢量绘图与持久节点，不增加图片或每帧重建界面。持续时间改变后提升配置版本，沿用异版确认重开规则。

### 3.4 资源栏

在三个卡片内分别显示“粮 60”“木 60”“人 6/8”，保留图标，所有内容保持单行。用现有 k/m/b/t/q 缩写控制宽度，保留数字足够的阅读尺寸；验证人口 20/20 与最大安全整数显示。

## 5. 独立审核补充

审核通过，没有其他需要用户决定的关键问题。实施时落实以下边界：

- 建设行固定展示费用，另行展示原因；移除当前根据“原因是否含不足/仓储”决定展示内容的文案耦合，调整行高及滚动步长。
- 住房未满 5 间时可建议增建；已经 20 人时明确等待人口空位。清晨旅人选择不能建房，谢绝始终可用。
- 出生检查覆盖夫妻任一方已有的未成年孩子，包括再婚前的孩子；父母可亲自照料，无需第三位成人；没有终生孩子总数限制。父母劳作剩余不足不能靠等待恢复。
- 当天出生并照料，当夜可计入首次成长；成长、劳作、养老与生育间隔均按成功守夜推进。
- 农田最多 6 岗、伐木最多 4 岗，继续升级提高产量；粮食、木材分别受仓储上限约束。
- 说明入口不覆盖保存待确认、回前台继续提示、清晨待选或失败结算。切标签不提交命令，不解除其他暂停来源。
- 警钟现有倍率 1.5 提升为共用的有注释常量，战斗和文字引用同一值；保留与饥饿倍率 0.7 相乘。检查结束、重开、胜负、销毁后的效果清理，避免持有重绘前已销毁文本节点。
- 以真实攻击次数及完整 tick 生命周期验证警钟；倒计时和脉冲不通过整界面刷新驱动。
- 验证最长中文姓名、两行阻塞原因、每章末尾滚动可达及“粮 999.9k / 木 9q / 人 20/20”单行布局。
