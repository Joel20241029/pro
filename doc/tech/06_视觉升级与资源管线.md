## 2. 人物方向与真实遮挡

原来仅对正面行走帧左右镜像，不能表现向上移动。新增的两张 4列×6行动画母版覆盖 male_a、male_b、female_a、female_b、boy、girl。每组 4 帧；DOWN 用原帧，UP 用背面，RIGHT 用右侧，LEFT 镜像右侧。

同身份四方向保持相同画布、pivot、帧数与帧率。方向来自当前路线段位移，以 15% 主轴滞回减少斜向抖动；停止保留方向，专用劳动动作按原视角显示。动作和方向都不改变业务坐标、岗位产量、攻击节奏或存档。

所有建筑、树木、城墙和人物继续共用 World，按逻辑足底 y 与稳定 ID 排序，写入 zIndex，并由 stackingRoot 隔离 HUD/面板。裁边偏移由引擎 Texture 恢复，不额外加到人物坐标或排序键。

森林仅两个合并占地，左右木栅各一个合并占地，避免把每株装饰树都变成导航节点。城门两边各保留 40 逻辑像素侧道，扣除足底间距后仍可通过。敌人原道路、到门处理和塔伤害不因这次环境表现改变。

## 3. Tip 组件合同

[Tip.ts](../../project/LayaProject/src/view/Tip.ts) 继承 Laya.Sprite，由 GameView 创建一次，放在最上方独立显示层，位置为 720×1280 游戏安全区的中心 (360,640)。使用独立浅麦金 panel_tip 九宫格（32×32，固定边 6，767 字节），文字为深棕色配细暖白描边。卡片宽 600，文字宽 536，字号 34，水平/垂直居中。卡片高度随 textHeight 增长，最大 800；过长文字省略显示，业务原始错误仍保留。Tip 和其文字不拦截点击。

| 时间 | 视觉状态 |
| --- | --- |
| 0～0.16 秒 | alpha 从 0 淡入到 1 |
| 0.16～1.72 秒 | 保持清晰 |
| 1.72～2 秒 | 淡出 |
| 达到 2 秒 | 隐藏，不占点击区域 |

`show(message)` 替换上一条并重置时间轴；`advance(delta)` 由唯一帧循环调用，不另建 Timer 或 Tween 回调。打开菜单不会暂停 Tip 倒计时；BACKGROUND/DISABLED 不推进。GameView 销毁时随 root 一起销毁。

GameSession.error 保留原有读取/赋值接口，新增纯运行时 errorRevision。每次非空错误赋值递增，包括同文案再次触发；GameView 只在新 revision 时弹提示，普通面板刷新不会让旧错误复活。保存等待时消费 revision，但继续显示专用保存面板，不弹短 Tip，也不因为两秒结束而清除错误或确认保存成功。

配色参考 Adobe 关于相邻色协调的说明，并用 W3C 的文字对比原则核对深字浅底。具体麦金色为本项目选择，非外部模板复刻：[Adobe 色轮](https://www.adobe.com/uk/creativecloud/design/discover/color-wheel.html)、[W3C 对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。制作源为 village_tip_v4.png 与 visual_v4_prompts.json，旧 v3 母版保留。

## 4. UI 布局与源资源

字体、颜色、行高、面板尺寸、Tip 时间等统一放在 [UiTheme.ts](../../project/LayaProject/src/view/UiTheme.ts)。名单、家庭和传承等九类列表均上下滑动；内容区宽 600，滚动条单独留边，标题、右侧关闭按钮及家庭主操作固定。地图上单独的“家园”标签已移除，资源条保留。不能为了放下更多内容把字体重新缩小到不可读。

建设面板标题按功能分色：住居/城防为蓝色、农田为森林绿、伐木为木棕色；费用保持深棕正文，仅不足分子标红，说明用浅棕。原有居中与按钮内边距保持。

所有按钮文字都按皮肤内边距布局。家庭姓名与“迎接孩子”合成一行；名册的身份和岗位仍为双行，需要更高的卡片。名字通过本机 Laya 3.4.2 已有的 `Text.html` 与 `<font color>` 实现；姓名内容先转义，颜色标记不改变按钮点击回调或数据结构。

资源费用统一使用 `resourceCost(owned, required)` 生成“现有/所需”。当 `owned < required` 时，仅分子使用 `C.red`，配 1 像素暖白描边；`owned >= required` 时不插入颜色覆盖，继承所在按钮或说明的正常颜色。建民居、农田/伐木场升级、修门、防塔新建/转型/升级均直接读取 RULE/TOWERS 的实际费用；迎接孩子的粮食费用放在家庭与照料者面板的说明区，家庭按钮继续保持单行。防塔按钮保持两行，费用写作“木 现有/所需”。

此颜色只表示该项资源是否足够，不代替年龄、容量、白天阶段等业务条件。满级、民居上限、完好的城门、已建成的当前塔型显示状态文字，不展示无法执行操作的费用。人口/容量、成长、等级、城门血量和驻塔数量不套用费用标红。原有按钮可用性与命令校验保持原语义；已确认操作触发刷新时，数量和颜色跟随最新状态更新。此调整由真实 Text 绘制，无新增 PNG、图集或原始美术素材。

新 UI 母版生成后存在微弱辉光，整格 alpha 外接框会把宽按钮缩成中央小块。因此 recipe 保存人工核对的可见轮廓源裁窗，再 stretch 到九宫格基准画布。parchment 的 48 像素固定边包含角纹；左上麦穗不再绘制，关闭按钮保留右侧框内。字体和交互代码不会反向成为制作源数据。

“去掉按钮阴影”指移除 button 中额外画的暗色底座，按钮原 PNG 的轮廓与高光仍保留；该阴影不是原图的一部分，因此无须破坏原始母版。母版、裁窗、边距和用法在资源文档中同步维护。

## 5. 可重复的资源构建

稳定输入为 [asset_recipe.json](../../res/source/asset_recipe.json) 和 source 母版。配方不从已生成的 manifest/atlasRect 反推裁图，因此任何重新排图都可重建。

```bash
node /Users/happyelements/Documents/pro/res/tools/build-resources.mjs \
  --work /Users/happyelements/Downloads/daidai-wechat-visual-20261110/work/assets \
  --sync
```

流程：读取母版与裁窗 → 生成分类完整画布 → 仅对图集做透明裁边 → 按 world/ui 分类分页 → 检查像素与动画 → 写台账、报告、动态预览 → 同步运行白名单到 Laya。临时裁片放 Downloads；制作资料不进微信包。

当前 173 张源画布、32 组动画、108 张帧、2 页图集。148 张图可裁边，内容占用节省 170,805 像素（16.37%）；页面仍为 1024² 与 512²。面积节省不等同文件体积节省，补齐男女老人动作后运行资源合计 1,300,061 字节。

源文件包括两个方向母版、新木栅母版、新 UI 母版、[本轮提示词](../../res/source/visual_v2_prompts.json)、[生成记录](../../res/source/generation_records.json)，旧源图全部保留。散图、动画条带、GIF 与 [动态预览](../../res/preview/index.html) 同步重建。

## 6. 九宫格资源缩小

保持原固定四角，中心及边条在可拉伸方向压为 2 像素。原基准图通过 nineSliceSourceSize 记录，运行画布改用紧凑尺寸：parchment 98×98，card/四种按钮/portrait_frame 30×30，Tip 独立 32×32。构建逐像素验证四角；可拉伸区渐变会简化，必须看实际拉伸接缝。

九宫格 v3 历史优化从 1,450,325 减至 1,384,589 字节。随后统一人物并补齐劳动动作降至 1,172,578 字节；当前增加男女老人动作后为 1,300,061 字节。没有对人物和建筑降采样，UI 页尺寸仍为512×512，纹理显存没有随文件字节减少。原母版、制作配方与拉伸预览均同步保留。

## 7. 箭矢、抛石与命中表现

原实现把塔顶与目标直接连接成一段线；现有图集中的 `fx_arrow`、`fx_stone` 尚未用于战斗。此次复用原素材，箭矢与石块的分类散图均为 48×48，中心 pivot 为 (24,24)。原始制作源仍是 [effects.png](../../res/source/static/effects.png)，裁窗、画布和用途保存在 [asset_recipe.json](../../res/source/asset_recipe.json)；不重复生成、导入同内容图片。寒塔同时接入已有冰球与霜环。

| 类型 | 飞行图 | 720 逻辑画布显示宽度 | 飞行 / 命中时长 | 飞行形态 | 命中图 |
| --- | --- | ---: | --- | --- | --- |
| 箭楼 | fx_arrow | 68 | 0.24 / 0.15 秒 | 原图朝右，按起终点方向旋转并直线飞行 | fx_hit |
| 石塔 | fx_stone | 72 | 0.40 / 0.20 秒 | 抛弧最高偏离直线 48 像素，自转 360 度/秒 | fx_hit |
| 寒塔 | fx_ice | 60 | 0.30 / 0.20 秒 | 轻抛弧 12 像素 | fx_slow_ring |

显示宽度包含原画布透明边，不能直接当作可见物体宽度。起点沿用塔位 y−35，终点沿用命中点 y−20；箭矢按原图向右的 0 度方向旋转，裁边后由 Texture 恢复中心。命中阶段在同一显示节点中换图、放大并淡出，不新增伤害、音效或第二次减速。

[ProjectileMotion.ts](../../project/LayaProject/src/view/ProjectileMotion.ts) 只读取已结算的 Shot 与实际战斗 tick。年龄为 `(battle.tick - shot.tick - 1) * RULE.step`：step 完成时 tick 已自增，因此最新发射的效果从零开始，暂停不推进，倍速跟随实际模拟步数，不另建计时器。WeakSet 防止同一个 Shot 因面板刷新反复播放。接收后独立保留 Shot 引用，即使原五 tick 队列已经删除该项，石块仍能完成飞行。

GameView 在既有 shots 层一次性创建 `RULE.effectCap`（32）个精灵，飞行和命中共用同一个槽，超过上限沿用只保留最新装饰的规则。切换战斗实例、结束战斗或回到白天时立即清空；最后一发可被结算切换截断，胜负与保存不等待动画。原目标死亡后不追踪已回收节点，落点仍为该次攻击记录的坐标。

## 8. 守夜面板暂停与成家表现

塔面板原先同时添加 USER 和 CHOICE 暂停，关闭只移除 CHOICE，导致看似卡死。现在打开/关闭只配对管理 CHOICE；夜间 reassign 接受 USER 或 CHOICE，仍拒绝未确认保存。原有手动、后台、回前台确认暂停继续各自管理。微信实际按钮链已核对调任、释放、取消关闭后 tick 继续；原先手动暂停仍需点击继续。

成家会合、两人各自头顶红心、男女完整劳动动作及原始资源更新见 [07 人物动画审计与自动岗位](07_人物动画审计与自动岗位.md)。
