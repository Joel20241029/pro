# 代代守村：防塔自动驻守

日期：2026-11-11。本篇交付配置版本：8；后续配置 9 延续本篇规则，最新验证见 [17](17_条件提示与玩法说明.md)。用户要求已建塔有合适村民就自动配置，保留玩家指定人选，取消“释放当前驻守”。本轮同时交付 [异版存档重开修复](15_异版存档重开修复.md)。

## 1. 规则与交互

- 驻塔人选必须已成年且劳作剩余夜数大于 0。孩子与退休老人不参与；白天耕作、伐木和照料者都能在夜间驻塔。
- 已建塔按塔位顺序补人；候选沿用在村列表顺序，每人最多驻守一座塔。保留已有驻守，只有空塔参加自动分配，不按天赋重新洗牌，也不消耗随机数。
- 驻塔不占白天岗位，不取消生产或照料。村民不足时留下空塔，地图和面板显示“成年村民不足”。
- 玩家可以手动选人。选择尚未驻塔的人时，替换目标塔的驻守者；选择其他塔的驻守者时，两塔人员直接对调。目标原本为空时，原塔再按可用人数自动补位，不将刚选中的人调走。
- 塔面板保留“更换驻守村民”，取消“释放当前驻守”。更换成功后直接回到村庄。
- 夜间打开面板仍使用原有临时暂停；选人完成或关闭面板后解除该临时暂停。玩家主动暂停不被解除，仍需点击继续守夜。
- 夜间调整只作用于本场战斗运行态；不会覆盖战前快照，进程重启仍从已经保存的战前安排重放本夜。胜利后才结算当前驻守结果并处理退休接班。

## 2. 触发时机

| 时机 | 行为 |
| --- | --- |
| 新建村庄 | 保留两座初始塔的既有人选，自动补位逻辑不重排 |
| 白天建塔或改建 | 新建空塔立即安排人；改建保留原人选 |
| 守夜胜利清晨 | 处理成年、退休及寿终清理后补塔；新成人即有驻塔资格，生产岗位仍等待专长选择 |
| 清晨选择 | 旅人接纳、成年专长等选择完成后补空塔；谢绝旅人不增加人口 |
| 开始守夜 | 再按当前人口补空塔，然后锁定经济与战前快照 |
| 玩家更换驻守 | 先完成指定替换或对调，再为其他空塔安排剩余成人 |

成年资格复用 `GameState.isWorkingAdult()`。没有新增性别、职业或动画资格限制，也没有改变人物劳作寿命、塔伤害、射程、造价、产出和口粮。

## 3. 实现与版本边界

| 文件 | 改动 |
| --- | --- |

| [tower-staffing.test.cjs](../../project/LayaProject/tests/tower-staffing.test.cjs) | 13 项自动驻塔、命令、暂停、存档及面板回归 |

`OPERATOR` 命令与驻塔接口不再接受 `null`。运行时对空 ID、缺失人物、孩子、老人和未建塔保留明确错误，不将非法输入默默改为其他人。

本轮未改变存档结构，不兼容旧配置进度。玩家遇到其他版本时走明确确认的重开界面；同版正常读档。开发交付后按既有约定人工清理两个本地测试存档键，游戏启动不会自动清档。图片、动画和图集未修改或新增。

1. 使用原有配置 7 的测试双槽启动配置 8，显示异版确认界面；调用实际按钮点击回调后进入第 1 天、6 名村民，两个槽均为配置 8，无保存待确认或错误。

3. 在驻塔列表选择已在第一塔的青竹，第一与第三塔直接对调；面板关闭，暂停集合为空。
