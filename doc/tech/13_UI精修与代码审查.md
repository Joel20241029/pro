# UI 精修与代码审查

日期：2026-11-11。本轮交付配置版本：6。后续配置 7 的塔位和表情距离调整见 [14](14_塔位覆盖与表情距离.md)。本文工作范围为用户反馈的资源栏、空列表、头顶表情、按钮图标联动，以及当时全部自有游戏代码的审查与必要清理。导出目录仍为 `tryVersion/wxgame`。

## 1. 修改依据与实施方案

用户要求顶部资源保持单行，大数可使用 `111k`；人物头顶不再显示文字 Tip，改成表情彩蛋；空列表提示放大并全界面居中。按钮要求以最后一次纠正为准：保留图标，修好与按钮底板、文字的按压联动。

复用现有 `button` 面层、`ScrollList`、人物彩蛋调度和 `SpriteFrames` 加载管线。没有新增按钮框架、每人计时器或单独资源下载流程。改动方案由独立审查分别覆盖 game/storage、平台与开放数据域、view 三部分，主代理统一修改。

代码清理仅删除已核实的无引用或重复内容，修复确认存在的缺陷。存档完整性、暂停状态、异步回调隔离和业务预检有实际职责，继续保留。源资源、配置、文档与微信导出同步更新。

## 2. 资源栏与空列表

- 顶部每格仍为 212 × 74 逻辑像素，只保留图标和单行数值；去掉第二行“粮食／木材／村民”名称。
- 数值字号为 34，`wordWrap=false`，图标与数值在各自区域垂直居中。
- 顶部粮食／木材使用千进制：`k / m / b / t / q`，低于 1000 显示原整数，缩写最多保留一位小数并向下截断。例如 111000→111k、999999→999.9k、1000000→1m。
- 缩写只影响顶部显示。面板沿用万／亿，所需费用仍为精确整数；资源比较、扣费和升级计算使用原始值。
- 通用人物／家谱空列表使用 34 号字，水平和垂直居中于面板中央。家谱显示“家谱暂无记录”，其他候选列表显示“暂时没有可选的人”。
- 空列表不创建透明滚动容器。家庭空态同样居中，固定“让两位村民成家”按钮继续可用。

## 3. 按钮按压联动

原问题是 `button()` 只移动第一个面层，而调用方把图标或头像挂到了外层按钮，导致按下时只有底板／部分文字移动。

现在所有可见内容都属于 `buttonFace`：

| 按钮类型 | 一起移动的内容 |
| --- | --- |
| 底部村民／家庭／建设／家谱 | 九宫格底板、文字、小图标 |
| 建设／塔升级条目 | 底板、侧边色条、图标、标题、效果、费用 |
| 人物／家庭候选条目 | 底板、姓名和说明、头像框、头像 |

外层热区位置、尺寸与点击监听保持固定。面层及装饰仍不接收鼠标事件，避免影响滚动容器的点击取消。沿用 `MOUSE_UP / MOUSE_OUT / UNDISPLAY` 复位；禁用条目不注册按压和点击。没有标题的自定义条目不再创建空 `buttonText`。

## 6. 随机整数缺陷修复

审查发现原 `range(n)` 使用 `v % n`。LCG 低位存在周期，在出生固定抽样顺序下，父母天赋二选一会锁定一侧，精英比例也可能随种子偏到约 4% 或 8%。既有“完整 32 位阈值”只修复了性别，未覆盖这些调用。

现在采用等宽高位分桶：

```ts
const bucket = Math.floor(0x100000000 / n);
const limit = bucket * n;
let v: number;
do { v = this.next(); } while (v >= limit);
return Math.floor(v / bucket);
```

接受区间恰有 n 个等宽桶，每个结果对应相同数量的原始值。范围校验和拒绝区间保持一致；同样的范围调用序列消费相同数量的原始随机数。新抽样可能改变后续玩法分支和同种子整局结果，所以配置版本升至 6。精英概率仍为已确认的 5%，天赋仍从双亲中随机继承，不修改经济或寿命规则。

按用户既有决定，交付前人工清理本地开发双槽，不提供旧版迁移；同版重进正常保存和继续，云端最高纪录不清除。
