## 3. 美术与尺度合同

暖色像素风，深棕轮廓、土黄屋顶、陶红与橄榄绿衣服；村庄为轻微俯视的正面三分之四角度。建筑、敌人和人物使用明确轮廓，小尺寸可辨认。文字和数字由 Laya 文本节点绘制，PNG 不带游戏标题、数值和按钮文字。

输出像素尺寸是候选纹理画布，不是强制世界占地。地面路径与命中距离来自逻辑配置，不根据图像宽度或阴影推算。displaySize 给出初次接入的原尺寸起点；P1 可以调整显示比例，但要统一同类对象的视觉尺度。

角色使用整人帧，不是身体、头发、衣服分层部件。appearanceVariant 只选择有限配套造型；同一身份的外观变化不改变性别、天赋、专长或亲缘。若后续要求自由拼部件，需要另做美术和资源合同，不能把本批帧称为已有可拼接系统。

成人任意性别、天赋仍可承担 GDD 允许的全部岗位，资源覆盖不能变成岗位限制。本批只有上表列出的专用劳动动作。其他“身份 × 岗位”组合的明确表现建议是：使用该身份 walk 的 restFrame，叠加对应岗位图标；不更换另一个人来冒充该身份的工作动作。此方案用于首版有限美术覆盖，后续如需每个身份都有种田、伐木、照料、守塔动作，可按相同 2～4 帧合同增补。

照料者以本人静止帧站在孩子附近，显示照料图标；孩子播放婴儿待机或儿童行走。到塔位后显示本人静止帧/头像，塔自身用回弹和投射物表现攻击。没有专门的人体射箭、受击、死亡、退休行走或四方向动作包，不宣称本批已经提供。

婴儿与长者只属于外观表达：婴儿没有引入第三种业务年龄阶段；退休长者不恢复生产或塔位。成人从成年到退休前也不会因为剩余夜数低自动改变为另一个老人身份。

### 4.3 时间与播放行为

| 情况 | 规则 |
| --- | --- |
| 当前动作持续播放 | 按累计动作时间计算帧号，不在每次刷新时归零 |
| 动作发生切换 | 从新动作的第 00 帧开始；frameCount 来自配置 |
| 人物停止行走或劳动 | 使用该动作定义的 restFrame，不继续原地踏步 |
| 白天生活表现 | 使用场景表现时钟，前台未阻塞时推进；不产粮、不成长 |
| 夜晚表现 | 使用战斗推进时间，跟随暂停与 1/2 倍速 |
| 进入后台、保存等待或场景禁用 | 停止动作时钟，返回不补播后台经过时间 |
| 界面临时隐藏后显示 | 同一动作实例保留累计时间；被销毁重建从首帧开始 |
| 缺失 animationId / frameId | 资源校验失败并明确报错，不任意挑另一动作 |

建议统一帧选择公式：`floor(elapsedMs × fps / 1000) % frameIds.length`。使用共享更新入口，缓存 134 个帧纹理映射；不能每帧创建纹理、加载图片或给每个人新开 Timer。序列帧只有显示责任，HP、射程、出生、成长和退休均由业务状态决定。

## 5. 切片、锚点与图集

### 5.1 源图不能直接假定等分

母版生成要求等格排布，但实际 UI 图标和部分敌人行边界有偏移。本轮以检查后的 sourceRect 切片；UI 底板使用逐个对象的明确矩形。manifest 同时记录原始母版路径、sourceRect 与 sourceCropWithinCell，便于重新导出。

动画每行 4 帧共享同一行裁切口径和画布，不对每张帧按可见轮廓单独缩放或裁边。相邻帧有正常的腿部抬起与身体轻微起伏，不用逐帧脚底强行重对齐抹掉动作。四帧条带用于检查不应出现的整个人横跳、尺寸漂移和邻格残片。

### 5.2 坐标字段

| 字段 | 含义 | 单位 / 原点 |
| --- | --- | --- |
| sourceSheet | res 下实际母版相对路径 | 文件路径 |
| sourceRect | 从母版取出的矩形 | 原始图像像素、左上角 |
| sourceCropWithinCell | 静态图的局部裁剪，动画保留整格 | 单元格像素、左上角 |
| width / height | 导出 PNG 画布尺寸 | 输出像素 |
| untrimmedSize | 导出时的完整画布 | 与 PNG 尺寸一致 |
| trimOffset | 图集相对导出画布的裁边偏移 | 本批统一 0,0 |
| pivot | 相对输出 PNG 的定位点 | 像素、左上角，不是 0～1 比例 |
| atlasRect | 图集中的内容矩形，不含 2 像素间隔 | 图集像素、左上角 |
| displaySize | 初始建议显示尺寸 | Laya 逻辑像素 |
| plannedLayaPath | 散图模式下拟导入位置 | 尚不存在的路径，不能当作已引用资源 |

人物默认脚底定位点约为画布宽的一半、高度的 0.96；同一动作四帧精确一致。建筑和装饰约为 0.94 高度；UI 与特效按中心。最终值以 manifest 为准，Laya pivot 使用像素值而非误当 anchor 比例。地图 Y 排序使用角色逻辑脚底位置，不使用不同帧的包围盒底边。

图集不旋转、不逐帧 trim；每个资源外留 2 像素透明间隔。若采样方案使用线性过滤并出现边缘串色，需在资源管线中明确增加挤出边或改采样设置后再验证；当前不宣称已通过所有设备采样。像素风优先点采样，显示非整数缩放时也要检查实际画面。

### 5.3 自定义图集表

[frames.json](../../res/atlases/frames.json) 的 format 为 `daidai-village-rects`，含 pages 和 frames。每个 frame 记录 page、rect、sourceSize、trimOffset、pivot、nineSlice。它不是 Laya 导出原生 atlas 文件，不得直接当作 `Loader.ATLAS` 输入。

接入建议：加载页面 PNG 为 Texture → 验证每个矩形 → `Laya.Texture.createFromTexture(pageTexture, x, y, w, h)` 创建缓存 → `Sprite.texture` 切换帧。三个符号已在本地 LayaAir.d.ts 核对存在；加载与回收仍需实机测试。

如果后续采用 IDE 自动图集，就以 runtime 散图为源，生成 IDE 支持的格式，并维护相同逻辑 frameId 映射。两种方式选一种，不让同内容既出现在自定义图集又出现在原生图集中。

## 6. UI 九宫格与地表

### 6.1 九宫格起点

这些边距按最终导出尺寸设置，属于待 Laya 显示验证的 UI 参数。顺序为上、右、下、左、repeat；符合本地 UI sizeGrid 声明，不采用另一引擎的 left/top/right/bottom 顺序。

| 资源 ID | 画布 | top/right/bottom/left | repeat | 建议用途 |
| --- | --- | --- | --- | --- |
| panel_parchment | 128 × 128 | 20/20/20/20 | 0 | 通用面板 |
| panel_card | 96 × 128 | 12/12/12/12 | 0 | 人物或选择卡片 |
| panel_button_gold | 128 × 48 | 12/12/12/12 | 0 | 主要操作 |
| panel_button_green | 128 × 48 | 12/12/12/12 | 0 | 次级确认 |
| panel_button_disabled | 128 × 48 | 12/12/12/12 | 0 | 不可用操作底板 |
| panel_portrait_frame | 64 × 64 | 14/14/14/14 | 0 | 头像边框，中心透明 |

按钮文字独立，禁用理由仍可查看。三张按钮底板是三个独立皮肤，不是 Laya Button 默认的纵向三态条带；不要把单张图片误设置为多帧按钮皮肤。若使用 Button 或其他 UI2 组件，按该组件实际 skin 状态合同接入；也可由 Image/Sprite 与文本组合控制。

### 6.2 地表状态

4 张地表是 64 × 64 不透明地块，可以用于局部拼贴和简色背景上的材质块。本轮没有宣称严格像素无缝，接缝与重复感仍需地图接入检查。固定道路形状由逻辑路径和地面铺设决定，不把整张概念图作为游戏背景。

季节采用现有地块配色与 UI 图标，昼夜采用整体亮度/色调和炉火两状态；不另外制作四季四张大图。建筑升级用等级文字/徽标，房屋第二张是外观差异，不是新增房屋类型。

## 8. 资源台账与校验

[manifest.json](../../res/manifest.json) 为完整源台账，记录当前真实文件、尺寸、alpha、SHA-256、源裁切、pivot、图集坐标、动画归属、业务映射和拟导入状态。[animations.json](../../res/animations.json) 为播放合同；[budget_report.json](../../res/budget_report.json) 为字节统计；[validation_report.json](../../res/validation_report.json) 为实际执行的文件检查。

静态检查包括：134 PNG 可解码、18 组引用闭合、每组 4 帧、帧尺寸/pivot 一致、图集页内无越界/无重叠、透明资源的外圈透明、图集裁取像素与散图一致、资源分类计数、文件哈希和预算。生成四帧条带与循环 GIF 后，还需查看角色姿势、内容完整与明显跨格问题。

本轮已纠正发现的偏移切图与特效半透明底色问题。候选画风和动作可以用于首版接入；AI 帧之间仍可能有少量轮廓或细节漂移，正式接入时应按 A01～A09 检查身体尺度、动作切换和循环接缝。不能以脚本的“4 张不同文件”取代最终动画观感验收。

## 9. 后续增补规则

新动作先列 characterId、actionId、用途、帧数（2～4）、FPS、loop、restFrame、画布、pivot 和需要切换的旧动作；基于同一身份参考图制作。保持旧 frameId 不变，新增帧用连续编号，资源缺失时不默默换成另一人。

每次增补重新统计世界/UI 图集和最终导出包。原始高分辨率图片仅留 source，不能借动画增补逐渐把运行资源变成几十张大图。声音未在本轮请求的图片交付中生成，后续仍按原设计的短音乐与短音效预算单独准备。
