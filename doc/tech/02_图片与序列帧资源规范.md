## 3. 美术与尺度合同

暖色像素风，深棕轮廓、土黄屋顶、陶红与橄榄绿衣服。轻微俯视的村落视角，人物和建筑保持清晰轮廓。文字和数字由真实 Laya Text 绘制，PNG 不包含业务标题、等级或按钮文字。

画布尺寸不等同世界占地。建筑碰撞范围由地图底座配置明确给出，不能使用整个屋顶或树冠的图片矩形堵路。人物为整人序列帧，有限 appearance 只选择外观，不改变性别、亲缘、岗位或天赋；本批没有自由拼部件功能。

实际地图中成人宽 56、儿童宽 48、婴儿宽 42 个逻辑像素。显示按 sourceSize 保持比例；人物 pivot 为原始画布中的足底。方向切换、裁边、左右镜像均不改变逻辑脚底。

## 4. 动画与方向

### 4.1 村民覆盖

| 身份 | 原有动作 | 新增行走方向 | 每组帧数 / FPS |
| --- | --- | --- | --- |
| male_a | 正面行走、农作、砍树、照料 | 背面、右侧；左侧镜像右侧 | 行走 4/8，农作/砍树 4/6，照料 2/4 |
| female_a | 正面行走、收获、砍树、照料 | 背面、右侧；左侧镜像右侧 | 行走 4/8，收获/砍树 4/6，照料 2/4 |
| boy、girl | 正面行走 | 背面、右侧；左侧镜像右侧 | 4/8 |
| baby | 待机 | 不移动 | 4/4 |
| elder_male、elder_female | 正面待机、正面行走 | 背面、右侧；左侧镜像右侧 | 行走 2/4，待机 2/2 |

成人、儿童、老人共六个行人身份各有 DOWN / UP / RIGHT / LEFT 映射。DOWN 使用原 walk，UP 使用 walk_up，RIGHT 使用 walk_right，LEFT 对 walk_right 镜像。不再把正面帧左右翻转当作向上行走，也不在移动时切换为仅有正面的搬木动作。具体名称和 restFrame 以 [animations.json](../../res/animations.json) 为准。

朝向依据当前路线段的实际位移向量，以主轴决定方向，保留 15% 滞回避免斜向走动抖向；停止保持最后朝向。左右镜像围绕足底，不能围绕不同帧裁边后的中心。方向切换不重置行走周期。男女均已配齐农作、伐木和照料动作，到工位播放；劳动动作保持其原始视角，途中仍使用方向行走。

婴儿只播放待机；儿童有实际位移；老人使用对应性别的两帧慢走与待机，详情和寿终家谱使用老人待机的 restFrame。老人母版为 [elders_v6.png](../../res/source/animations/elders_v6.png)，完整提示词见 [villagers_v6_prompts.json](../../res/source/villagers_v6_prompts.json)。人体攻击、受击、死亡及自由换装均未提供，不用现有文件数量声称已完成。

### 4.3 时间与暂停

帧号为 `floor(elapsedSeconds × fps) % frameCount`。同一动作连续播放时保持累计时间；行为动作切换时重置。静止使用该动作 restFrame，暂停保持当前帧。白天按限幅后的前台时间推进，夜间按实际战斗 tick 增量推进，不重复乘倍速。菜单、后台、保存等待或禁用场景不补播经过时间。

启动时缓存全部帧纹理；每帧只换纹理引用，不加载图片，不为人物创建独立 Timer。序列帧不决定生产、成长、攻击或 HP。缺失帧、缺失方向或不可达站点明确报错，不偷偷替换其他人物。

## 5. 透明裁边、坐标与引擎接入

### 5.1 原始切图与图集裁边是两步

源母版先按照 recipe 的 sourceRect 和 sourceCropWithinCell 取图，输出完整 runtime 画布。动画同一动作的 2～4 帧共用固定裁窗和尺度，保留步态起伏，不逐帧放大到相同可见轮廓。普通素材用 contain；本轮 UI 先按人工核对的轮廓裁切，再 stretch 到固定九宫格画布。

UI 母版的淡辉光会让 alpha 外接框接近整格，不能用自动外接框覆盖已核对的按钮源裁窗。完整母版保留，裁窗写在 recipe，方便下次修改；图集构建不依赖上次产物坐标。

随后图集阶段只删除 alpha=0 的外圈。浅色衣服、白色高光和半透明像素均保留。九宫格不执行这一阶段裁边。页内不旋转，每张图外留 2 像素透明间隔。

### 5.2 坐标字段

| 字段 | 含义 |
| --- | --- |
| sourceSheet / sourceRect | 原母版及母版坐标矩形 |
| sourceCropWithinCell | 上述矩形中的制作裁窗 |
| width / height、sourceSize | 完整输出画布；不随图集裁边变化 |
| rect / atlasRect | 图集内紧凑内容矩形，不含间隔 |
| trimOffset | 内容在完整画布中的正向 x/y 偏移 |
| pivot | 原始完整画布中的足底像素坐标 |
| nineSlice | top、right、bottom、left、repeat |
| pages[].runtimeFile | 扁平导入目录中的实际页文件名 |

`frames.json` 为自定义 `daidai-village-rects` v2 格式，不是 Loader.ATLAS 可直接识别的原生 atlas。加载 JSON 后读取 TextResource.data，再按页表加载 PNG，创建一次共享子纹理：

```typescript
Laya.Texture.create(pageTexture, rect.x, rect.y, rect.w, rect.h,
    trimOffset.x, trimOffset.y, sourceSize.w, sourceSize.h);
```

已核对 Laya 3.4.2 的本机声明与引擎实现：Texture 保存 offset/sourceWidth/sourceHeight，Sprite 按显示尺寸缩放裁片与偏移。`applyFrame` 只用原 sourceSize 换算 pivot，不再次手动加 trimOffset。`Texture.createFromTexture` 只有五参数，不适用于直接传入本批恢复偏移。

### 5.3 当前裁边收益

148 张图片得到裁边。内容总面积从 1,043,612 降到 872,807 像素，节省 170,805 像素，约 16.37%。这是面积节省，不等于 PNG 字节节省；当前仍为 2 页图集。

## 6. 九宫格、文字和按钮

| 资源 | 基准画布 | top/right/bottom/left | repeat |
| --- | --- | --- | ---: |
| panel_parchment | 98×98（原基准160×160） | 48/48/48/48 | 0 |
| panel_card | 30×30（原基准112×128） | 14/14/14/14 | 0 |
| panel_button_gold / green / disabled / red | 30×30（原基准144×56） | 14/14/14/14 | 0 |
| panel_portrait_frame | 30×30（原基准64×64） | 14/14/14/14 | 0 |
| panel_tip | 32×32 | 6/6/6/6 | 0 |

构建先恢复九宫格原基准图，再保留四角、把可拉伸区域压到 2px。原边距不变；sourceSize/pivot 使用紧凑后的画布。四角逐像素检查；中心与边条渐变会简化，不能称整图严格无损。Tip 独立浅麦金底图只有 767 字节，没有木框和装饰描边。

通用弹窗使用木框羊皮纸，48px 固定边包含角纹；主界面顶部与底部使用 card。左上麦穗已移除，右侧关闭按钮位于框内；保留右下独立叶片，不进入中心拉伸区、不遮住滚动内容。所有皮肤均为独立图片，不是 Button 默认纵向三态条带。

按钮由固定点击区域、九宫格面层和独立文字组成，已按用户要求去掉额外暗色底座。按下只让面层下移 4 逻辑像素；抬起、移出、卸载显示时恢复。业务提交仍只在 CLICK 事件发生，不因按下效果重复触发。

720 逻辑宽度下，面板标题 38、正文至少 28、按钮 30、地图标记至少 24。浅色字使用深棕描边，深色字使用较细暖白描边；标题/正文/说明区分棕、绿和浅棕，主要操作用金色。文字横向居中，按钮文字同时垂直居中并避开边框；名单采用上下滑动的高双行卡片，家庭采用两行滑动条目（姓名与可用操作/首个阻塞原因），主操作按钮固定在滚动区外；九类列表均不再分页。男性姓名为蓝色，女性姓名为橘黄色。通用 Tip 另由独立类实现，在屏中用 34 号字显示，淡入淡出总共 2 秒，详见 06。

资源费用以“现有/所需”显示，不足时仅现有数量标红（`C.red`、1 像素暖白描边）；足够或恰好足够时继承正文颜色。建设、修门、防塔新建/转型/升级与迎接孩子共用这一规则；满级或无需操作时显示状态文字。人口、等级和成长不使用费用配色。数字及颜色继续由 Laya Text 富文本绘制，不烘焙进 PNG；源图与九宫格无需改动。

战斗投射物实际使用 fx_arrow、fx_stone、fx_ice，命中复用 fx_hit/fx_slow_ring，均沿用 effects 原始母版及 48×48 中心 pivot 画布。箭矢原图向右，由代码旋转朝向目标；石块的抛物线与自转由表现逻辑完成，无须新增动画帧。具体画布显示尺寸、飞行时长和节点上限见 [06 攻击表现](06_视觉升级与资源管线.md)。

文字与布局参数归 [UiTheme.ts](../../project/LayaProject/src/view/UiTheme.ts) 与 [GameView.ts](../../project/LayaProject/src/view/GameView.ts)。地表候选拼片尚未完成严格无缝验收，主地图仍采用程序道路、森林和装饰组合，不将整张概念图带入运行包。

## 8. 后续迭代

1. 在 source 保留新版母版与生成记录，旧母版不覆盖丢失。
2. 编辑 asset_recipe.json 的源裁窗、方向映射和九宫格参数，保持已有 frameId 稳定。
3. 执行 [资源 README](../../res/README.md) 中的重建与同步命令，检查动态预览和 validation_report。
4. 重新导出微信包，运行包白名单检查；更新文档与包体报告。
5. 手机微信另行检查前后台、触屏、采样边缘与长时间性能。

本轮源码、制作输入、导入资源和文档都属于交付的一部分。只替换 Laya 目录内的 PNG 而不更新母版与 recipe，会破坏重建链路，不能作为正式迭代方式。
