# 代代守村：1.0.4 全面屏与安全区适配

日期：2026-11-11。目标体验版本：1.0.4。配置版本仍为 10；本轮只改表现与窗口事件，不变更存档结构或玩法数值。方案已独立审查并获用户确认。

## 1. 问题与结果

旧版虽然启用了 Laya fixedwidth，仍在 Main 中将 720×1280 根节点缩小并居中。微信开发者工具 iPhone 12/13 Pro 的窗口为 390×844，安全区 top47/bottom810，舞台实际为 720×1558.15，而根节点仍高 1280、y151.08；扣除系统安全区后，约 70 个屏幕像素被上下额外留白占用。

现在根节点使用固定逻辑宽度 720 与真实窗口高度，背景铺满窗口，信息和按钮避让状态栏、微信胶囊及底部手势区。回收空间分配给地图，后续按战场与居民区约 68:32 调整，兼顾道路层次与村民活动空间。成人显示尺寸由 56 增为 64～68，儿童、婴儿和老人保留年龄比例，精英仍额外乘 1.25。建筑、人物和特效图片保持等比，没有拉伸原图。

城门上方只显示耐久数字和进度条，不再显示“城门”二字。粮、木、人保留统一的单行“现有/容量”。小面板仍保持紧凑，普通面板、遮罩和 Tip 按实际安全区域定位。

## 2. 平台依据与坐标

采用 [Laya 屏幕适配说明](https://layaair.com/3.2/doc/basics/common/adaptScreen/readme.html) 中固定宽度、随窗口变化高度的方式；窗口变化沿用 [Stage RESIZE](https://layaair.com/3.x/api/3.3/classes/laya_display_Stage.Stage.html)。本地微信适配器已把 `wx.onWindowResize` 转发为舞台事件，不重复注册原生监听。

微信 API 字段依据 [官方 minigame-api-typings](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)：`getWindowInfo` 类型声明包含窗口逻辑像素、窗口相对屏幕起点 `screenTop` 和安全区；类型声明不代替对实际返回字段的处理。胶囊通过 `getMenuButtonBoundingClientRect` 读取。安全区和胶囊先扣除窗口起点再乘 `720/windowWidth`，不拿 pixelRatio 当布局比例。

按已确认的设备边界规则：safeArea 缺失时，顶部使用实际 statusBarHeight 扣除 screenTop，底部使用窗口边界；胶囊宽高有效时才额外避让。不猜机型或刘海高度，不新增业务数据默认值。

2026-11-11 预览空白修复补充：本游戏为 `showStatusBar:false` 的全屏窗口，仅当 `screenTop === undefined` 时，以 `0` 作为窗口顶部起点；有值时保持原值。安全区上下边界与胶囊底边共用同一个局部起点。此分支已经用户确认，不使用 `screenTop || 0` 扩大到其他异常值。

## 4. 窗口变化保持游戏连续

尺寸变化不创建新 GameSession、不读档、不执行命令、不改随机序列、不重开奖励。行走位置从旧布局还原到基准地图再投影；若与新布局建筑底座相交，只把表现位置移到最近可行走边缘并重算路线。驻足人物映射到对应新站点，照料者的额外位置保留相对婴儿的偏移。

面板和滚动列表实例保留，仅重新居中；排行榜已有开放域组件调用 updateViewPort，同步触摸区，不重复创建或再次授权。遮罩覆盖整个窗口。布局刷新不调用 motion.sync，避免重建人物日程；当前婚礼、守夜计时、警钟、暂停来源和存档状态保持原值。

## 8. iPhone 12 预览空白修复

用户反馈 iPhone 12 预览仅显示深绿色背景和微信调试浮层。已确认一个可复现缺陷：缺少 `screenTop` 时，旧布局直接做减法，安全区、地图、弹窗坐标和人物缩放变成 `NaN`；窗口高度仍有效，因此背景和整屏遮罩继续显示。
