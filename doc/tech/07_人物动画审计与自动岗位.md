# 代代守村：人物动画审计与自动岗位

日期：2026-11-10。配置版本：`CONFIG_VERSION = 2`。本文件记录用户最终确认的两种成人外观、自动安排、换岗、旧档迁移和成家表现，覆盖前期按四种成人外观制作的说明。

## 1. 最终规则

- 成年男性统一 `male_a`，成年女性统一 `female_a`。姓名、性别、天赋、专长、年龄、亲缘、家庭和夜间塔位继续独立保存。
- 男女都能耕作、伐木、照料、驻塔；不按外观限制岗位。不采用中途讨论过的“缺劳动动画就禁选、原工人改待命”方案。
- 去掉主动“待命”按钮。内部 `WAITING` 表示没有空岗的“待安排”状态，仍消耗口粮，夜间可独立驻塔。
- 自动分配只填空岗，不顶替已有工人，不消耗 RNG，不自动指定照料人。农田和伐木场仍保留原容量。
- 先为有农艺、伐木专长的待安排成人分配对应空岗；剩余成人先补农田，再补伐木。每轮按 `people` 的现有顺序处理。
- 玩家可调岗。满岗时直接选择替换的工人，无需先让人待命；被替换者有其他空岗会自动补位。
- 初始岗位保持原配置，林川继续伐木，初始木材日产仍为 14。没有改外观来调整天赋或经济加成。

## 2. 动画审计结论与本轮收敛

审计旧版的 30 组、120 帧时，有 27 组可达，3 组无运行入口：长者待机、绿色衣服女性的正面搬运、杂兵换装。三者是已生成未接入，不是运行中已经播放的内容。旧版 120 帧解码后的可见像素均非完全相同。

本轮退出运行图集的共 10 组、40 帧：两种 B 外观的六组方向行走、B 男砍树、B 女搬运、长者待机、杂兵换装。新增统一男女砍树各四帧、照料各两帧，共 4 组、12 帧。最终为 **24 组、92 帧** ，都有实际播放入口；静态资源中仍有地表等候选素材，不把“所有动画已接入”扩大为“所有静态图都已使用”。

| 动作 | 组数 / 帧数 | 出现条件 |
| --- | ---: | --- |
| 男女成人正面、背面、右侧行走 | 6 / 24 | 地图移动；左向镜像右侧，驻足取对应静止帧 |
| 男孩、女孩三方向行走 | 6 / 24 | `growth = 1` 的儿童在家附近散步 |
| 婴儿待机 | 1 / 4 | 新生儿 `growth = 0`，在家前固定站点待机 |
| 男女农作 / 收获 | 2 / 8 | FARM，实际走到工作点并处于劳动停留 |
| 男女砍树 | 2 / 8 | LOGGING，实际走到工作点并处于劳动停留 |
| 男女照料 | 2 / 4 | CARE，到孩子家附近的停留点，播放两帧动作 |
| 五种敌人行走 | 5 / 20 | 对应敌人进入本夜战斗；后期敌人需达到解锁日期 |
| 合计 | 24 / 92 | 四向行走 8 FPS，农作/砍树 6 FPS，婴儿/照料 4 FPS，敌人沿原配置 |

照料动画不是跟随散步中的孩子。当前行为是前往孩子家前站点右侧 34、下侧 8 逻辑像素处，停留照料，再返回自己的家前站点；横向错开避免成人前景挡住婴儿，没有新增动态追踪寻路。人体攻击、受击、死亡序列仍未制作；守塔者到达后进入塔内隐藏，塔攻击由投射物表现。

## 3. 为什么婴儿不容易看到

出生后立刻建立 `growth = 0` 的孩子，世界宽度为 42 逻辑像素，小于成人的 56。婴儿在按人物 ID 分配的家前站点原地播放四帧待机，不在照料者怀中，也没有独立婴儿房。

第一次得到照料并成功守夜后，成长值变为 1，改用男孩/女孩形象；第二次达到 2 后成年。无人照料时不成长，失败夜不成长。若出生后马上守夜，婴儿阶段很容易错过。

打开菜单时世界动画暂停；人物详情与家谱本身是静态头像，明确读取 `restFrame`，不是动画播放器。观察动作应回到村落，等待村民走到对应工作点。

## 4. 业务与 UI 接入

- `GameConfig.ADULT_APPEARANCE` 是统一外观来源；`LABOR_CLIPS` 只负责表现映射，不能当作业务任职资格。
- `VillageRules.autoAssignJobs` 处理两轮分配。触发点为开村、生育、手动改岗、生产建筑升级、清晨成年/照料解绑/退休完成，以及接受旅人或选择专长之后。
- 新成人在专长尚未选择时暂缓自动安排，选完再分配，以免绕过专长优先规则。照料结束的成人可先补空岗，已有岗位不会在孩子选完技能后被抢走。
- `JOB.replace` 仅用于目标生产岗已满、申请人当前不在该岗的情况。替换对象须是该岗中的另一位在村成年人；完整校验后同时变更双方，再自动分配，不在中间抢占空位。
- UI 删除 WAITING 按钮，保留耕作、伐木和照料。满岗按钮显示“换人”；名册显示待安排人数。界面中的“待安排”不是可主动选择的工作。
- 内部 `JOB WAITING` 类型仍存在，语义是释放后重新参加自动安排，UI 无入口；有空岗时不会持续闲置。

## 5. v1 存档迁移

只明确支持 `schemaVersion = 1, configVersion = 1` 向配置 v2 迁移；未知版本仍阻止载入。旧封套先按原字段验证校验和、结构和引用，不先改版本号来蒙混校验。双槽均能读取 v1/v2，选最高有效 revision。

迁移克隆选中的状态，将 `people`、`history`、候选 TRAVELER 的 `appearance` 按性别统一。包含尚未成年的孩子，因为成年后会读取保存的成人外观。原在岗者不改岗，旧 WAITING 按用户确认的规则填空岗。

随后通过原 `prepare / commit / 读回确认` 写入另一槽，revision 加一，成功后才接受状态。原槽保留；首次 prepare 失败显示明确重试入口，不能掉入新用户开村页。写入后异常保留同一 pending，重试不再生成随机数、不再次扣费。损坏槽恢复仍沿用原来的恢复确认入口。

夜间迁移不重算粮木、缺粮状态、成人/照料快照、波次、年龄、塔位或 RNG；战斗继续按既有重进规则从战前基线重打。自动填岗仅影响之后的白天日结。自动安排人数提示只在最终接受状态后发一次，不能覆盖未确认保存错误。

出生和旅人仍保留旧版 a/b 外观随机抽样的位置，但输出统一外观，避免更换造型同时改变随后姓名、天赋、专长及村规随机序列。

## 6. 成家会合与红心

成家命令确认保存后，`VillagerMotion.sync` 比较本次与上次的当前家庭集合，只对新增家庭排队。初次加载、新开村和读档不补播既有家庭。

两人复用原导航走向篝火前的 `(330,990)`、`(370,990)`，先到者等待。双方到齐后面对彼此，在各自头顶播放 2.4 秒红心浮动、轻微缩放和淡出，结束后从当前位置恢复最新岗位日程。中途改岗只更新正常日程；进入夜晚、成员离村或新开村立即取消，不阻塞战斗。

红心复用 `fx_hearts` 原小图，每名池中人物预建一个子精灵。人物自身为 stackingRoot，红心和人物共享足底深度；使用人物 pivot 定位，反向缩放抵消人物镜像。每次刷新隐藏并重置池中红心，避免换人后残留。表现不写存档、不增加出生、不消费 RNG。
