# 代代守村：好友榜、精英村民与成家红心

日期：2026-11-11。配置版本：4。本文记录用户已确认的本轮规则、制作源、实现与验证边界，覆盖早期“没有好友榜”及所有成人统一 12/3 夜的表述。

## 1. 产品规则

| 项目 | 当前规则 |
| --- | --- |
| 排名分数 | 单局最高成功防守波数；失败波不计分，重开保留最高纪录，不累计不同村落波数 |
| 排行范围 | 微信同玩好友，按波数从大到小；同分并列，例如 1、1、3 |

| 本人入榜验收 | 必须在实际云上传成功后能在列表看到本人；当前后台隐私用途阻断，尚未完成真实验证 |
| 精英来源 | 每名新生儿和每位来访旅人各独立 5%；开村人普通，不直接遗传 |

单机经营与存档仍独立运行。好友榜需要微信联网能力；没有增加联网生产、对战、云存档或离线收益。

## 2. 实现与数据边界

### 2.1 精英生成与寿命

`GameConfig.ELITE` 是精英数值唯一来源；`Person.elite` 是必填布尔值。出生沿持久化 family RNG、旅人沿 world RNG 抽取，精英结果与原命令一起提交。保存失败重试、刷新界面、退出再进入均不重新抽取。

`VillageRules` 在新人成年、旅人创建、成人荣休时按 elite 取寿命；所有人仍走原夜间快照、养老、寿终和家谱流程。`StateValidation.validatePerson` 同时用于在场人物、历史人物和待选旅人，验证标记、创始人普通规则和对应寿命上限。

存档 `CONFIG_VERSION=4`，没有旧数据补字段或迁移。开发交付只人工清 `daidai_village.save.a` 与 `.b`，立即重载；同版本重启保持进度。云榜纪录不是本地开发清档对象。

### 2.2 主域与开放域

主域仅发送已提交的 `legacy.bestNight` 和面板指令。`Main.onUpdate` 在无待保存事务时通知 `WechatPlatform.syncBestNight`；同一分数只通知一次，消息异常不进入 `GameSession` 保存错误路径。

好友头像、昵称、好友数组及托管成绩全部在 `build-templates/wxgame/openDataContext/` 内读取、排序和绘制；主域只显示 sharedCanvas，开放域不向主域回传好友信息。没有自建服务器，也不使用模板的随机示例用户。

| 文件 | 职责 |
| --- | --- |
| `src/platform/WechatPlatform.ts` | 微信存储、生命周期、单向消息、用户主动进入榜单后的原生隐私与朋友权限流程 |
| `src/view/SharedCanvasTexture.ts` | 固定共享画布的首帧分配与后续 GPU 子图上传，避免 WebGL2 重复分配不可变纹理 |
| `src/view/RankingView.ts` | 共享画布组件、完整父坐标转换、授权回调代数、计时器和私有纹理释放 |
| `openDataContext/score-store.js` | 数值解析、排序、同分名次、串行读云端最大值再写入 |
| `openDataContext/index.js` | 面板可见状态、请求代数、加载/失败/空榜、独立成绩同步队列 |
| `openDataContext/render.js` | 微信 Layout 的滚动列表模板，暖色背景、长姓名省略、空榜与异常提示 |
| `openDataContext/engine.js` | Laya 3.4.2 自带的微信 Layout 模板引擎，保留原文件与 MIT LICENSE |
| `src/WechatBuild.ts` | 官方构建插件：排除默认示例头像和 render 目录，每次从制作源重建开放域 |

### 2.3 成绩同步

云存储键固定为 `daidai_best_defended_waves_v1`，值为十进制非负安全整数。更改此键会形成新榜，不能用换键方式清开发存档。

1. 收到新纪录后读取本人云分；缺少 key 表示尚未提交，读取失败与坏值不等同于 0。
2. 取云分和当前待写最高纪录的最大值，只在增高时写入。
3. 上传中来的更高分合并并串行处理；关闭榜单不打断队列完成，不留下 busy 状态。
4. 失败不循环重试；重新打开榜单、产生新纪录或新会话重新载入时再尝试。
5. 本人分同步完成后才读取好友榜。无有效正成绩的好友不进入榜；坏值单独提示未参与排名，不伪装成 0 分。

微信 KV 没有原子 max 接口。这能保护当前会话顺序和已读取的旧高分，不承诺两台设备同时写入的服务端原子性，也不是防篡改的全网排行榜。

### 2.4 权限与后台配置

`scope.WxFriendInteraction` 是朋友信息权限；隐私指引授权是另一层要求。仅打开榜单时直接运行授权流程，平台原生弹窗由用户决定。不再提供“刷新榜单”“好友权限”按钮，也不主动打开微信设置页；拒绝授权沿用明确状态文字，关闭后可重新进入。

2026-11-11 开发者工具实测返回 `authorize:fail please go to mp to announce your privacy usage`。随后正常完成首波，本地 `completed=1 / bestNight=1`，云成绩读取仍返回 `getUserCloudStorage:fail please go to mp to announce your privacy usage`；本人资料读取也被同样拦截。因此不能将本地成功结算等同于云上传成功。当前保留关闭入口，不生成假好友、不绕过权限。

待后台确认的用途文案：

> 为展示好友守村榜，读取同玩好友的头像、昵称和最高成功防守波数，仅在微信开放数据域内展示，不传入游戏主域或自建服务器。

需在小游戏后台的用户隐私保护指引中选择对应朋友信息项目、填写用途，并完成平台要求的发布。已向用户提出具体文案；后台状态变化和真实好友展示必须另记验收结果，不能把本地测试当成后台已开通。

## 3. 共享画布与生命周期

- 使用已存在的 `Laya.OpenDataContextView` 与本地 Layout 模板，不额外加载一套 Laya 引擎或插件。
- 逻辑画布为 600×680，20 FPS；面板内位置为 (34, 132)，删除旧副标题和额外按钮后把空间用于列表。`Laya.SpriteUtils.getTransformRelativeToWindow` 合成面板偏移、游戏根安全区缩放和舞台变换，不能重复乘设备 DPR。
- Laya 3.4 的首次画布尺寸变化会直接使用 `_graphics.repaint`；构造时通过公开 `graphics` getter 初始化，避免首次打开报错。另外固定画布在入舞台前用 `Texture.setTo` 对齐画布、位图、纹理及源尺寸，避免组件残留 200×200 缓存导致每帧重新分配 GPU 纹理。`SharedCanvasTexture` 首帧分配，后续使用引擎 `setTextureSubImageData` 更新 GPU 内容，避免 WebGL2 重复 texStorage2D 的 immutable 错误；不在主域调用 getImageData 或读取好友像素。引擎升级时复核单点 `_texture` 内部句柄适配。
- 榜单打开沿原 CHOICE 暂停守夜；关闭只释放该暂停原因，手动暂停仍保留。
- 关闭时 Layout 清绘制、触摸与图片池；主域清计时器并释放组件独有纹理。延迟授权/好友响应用请求代数隔离。
- 切后台不重建榜单、不再次请求授权；回前台沿现有“继续游戏”流程恢复。尚未完成的隐私授权回调若面板已失效，不继续下一层朋友授权。
- XML 字段先转义再通过 Layout 真实支持的 `attrValueProcessor` 单次解码，昵称中的 `&`、引号、尖括号与头像 URL 查询参数保持原意，不能注入模板节点。
