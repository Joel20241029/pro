# 长期经营、五塔防线与怪物重制

日期：2026-11-16。状态：已按确认方案实施，并成功上传体验版 1.0.24；微信平台确认覆盖当前体验版本，构建标识为 `1.0.24-f086e4721d99`。本地验收与正式上传记录见文末，未提交正式版审核或发布。

## 1. 本轮目标与已确认边界

玩家希望建设、人口、战技和守夜长期都有可做的选择，而不是早早完成扩建、学齐全部战技，随后只面对血量不断增长的敌人。

- 初始仍有两座已建防御塔，总塔位改为五个，其余三处由玩家建设。
- 村庄保持现有地图大小，不改成可拖动的大地图。
- 用户随后修正了无限扩建要求：住宅扩建可以封顶在 100；每级增加的人数应减少，目的是增加长期建设选择，不是让人口过多。
- 外观变化分散在前 50 级；最后外观之后继续数值成长，不无限增加建筑尺寸或美术数量。
- 农田、伐木场、仓储修缮、城门和塔继续保留数值升级；本轮不增加它们的玩法等级上限。
- 战技拉开学习节奏，未揭晓内容不直接显示全套名字、图标和效果。
- 三种塔复用一个小体积发射音效；替换守夜音乐，去掉鼓和密集打击乐。
- 守夜压力更多来自数量和阵容组合，个体强度仍保留成长。
- 十类怪物全部重新设计，沿用五种小怪、五种首领；魔兽式奇幻轮廓与材质，仍然是高清预渲染二维，不引入实时三维。
- 全部怪物重新校准脚点、阴影和配件；提高有效行走帧数，同时控制战斗分包体积。

本方案的人口增量、战技波数/费用、神秘条目、造型与帧数已获用户确认；经济和波次系数获授权通过模拟调平。

### 2.2 阴影排查边界

已用微信 IDE 创建离屏精灵，实测透明裁图和 `Sprite.size` 会正确响应尺寸变化。因此本次不能未经验证就把原因归为纹理缓存或引擎缩放失效。

基线逐帧检查发现，各类身体的实际落脚位置不同，却共用 `(48,92)` 地面点，原阴影纹理自身的透明留白还会使图像中心偏离接地点。绘制矩形包含透明区域，`getGraphicBounds` 不能代替像素级脚底定位。本轮改为逐类固定脚点，独立阴影按实际可见轮廓中心对齐；身体帧保持统一画布，不再通过每帧的 Alpha 包围盒重新居中。

## 3. 方案比较与选择

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 只去掉房屋和人数上限 | 固定地图越来越挤，工作岗位不够，存档和列表增长失控 | 不采用 |
| 向下扩展可拖动村庄 | 每栋建筑都能真实铺开，但改变地图操作与一屏玩法 | 用户选择保持当前大小，不采用 |
| 固定地图、100 级住宅扩建、小幅增加容量 | 增加建设目标，后期外观稳定，经营与绘制规模分离 | 采用；具体数值已确认 |

## 4. 住宅、人口与建筑外观

### 4.1 住宅扩建

住宅扩建从 1 级起，最高 100 级；开局容量 8 人，每升一级增加 1 人容量，最终 107 人。扩建只增加容量，不直接赠送村民。

将现有 `houses` 字段的含义明确改为扩建等级，初始值改为 1；界面显示“住宅扩建 · 1/100 级”和“容量 8 → 9 人”，不再使用“100 间房 × 4 人”的含义。配置版本统一提升，沿用现有明确提示后重开的版本策略，不添加旧档迁移。

出生、成家、照料、旅人、退休和口粮沿用现有规则。住房满时提示扩建缺口；扩建到 100 级后，提示已达住宅扩建上限，不再继续诱导扩建。最高守夜纪录保持独立，不因开发清档而删除。

### 4.2 显示人数与真实人数分开

地图最多绘制现有规模的 20 名活动村民，全部真实人口继续参与工作、家庭、生育、养老和口粮结算。名册与家庭面板保留完整可操作记录。

可见人物集合采用稳定身份，不在每帧随机换人。正在成家的两人、地图反馈涉及的人以及可见孩子与照料者必须成组处理。驻塔者仍按既有行为进塔隐藏；夜晚只让当前可见居民围火堆，其他居民视为在屋内。

选择发生在 `VillagerMotion.sync` 之前，移动、火堆站点、照料、婚礼、表情和点击池都使用同一可见 ID 集合；不把完整经营状态覆盖成截断后的假状态。现有运动系统对超过二十名人物会因固定站点不足抛错，必须一并处理，而非只在绘制末端截断。婚礼或照料整组无法放入时，替换低优先级的完整组，不能选择半组。

不让地图人数上限反过来限制真实人口、劳作岗位或驻塔资格。不可见居民通过名册查看和调岗，地图不生成虚构的居民替身。列表仅创建可见窗口及相邻缓冲行，离开窗口的条目销毁，拖动后仍以稳定人物 ID 打开详情；现有 `ScrollList` 仅提供裁剪，条目窗口化是本轮新增工作，不宣称节点池复用。

### 4.3 外观均匀分布在前 50 级

复用已有十二个布局阶段，将表现阶段映射为：

```text
visualStage = 1 + floor(11 * (clamp(level, 1, 50) - 1) / 49)
```

外观阶段实际变化等级为 `1、6、10、15、19、24、28、33、37、42、46、50`。第 50 级以后固定最终外观，绝不再从最高档退回旧主体。

民居主体仍由修缮等级决定，厢房扩建由住宅扩建等级决定；两者各自在前 50 级完成有限阶段。左右两个住宅群的占地和名称继续保留；厢房数量固定在已有最高布局内，不按照真实容量生成几十个重叠部件。

农田、伐木场、城门、三类塔同样采用前 50 级的分布。所有布局使用已有足底、占地、攻击挂点和遮挡规则，达到大档后结构明显变化，中间小档增添支撑、护板和装饰。

## 5. 经济与成长公式

岗位也必须随设施成长，否则住宅扩建只会增加口粮负担。前三阶保留原有岗位数，之后农田、伐木场各每两级增加一个岗位；实际分配仍受工作年龄和可用人口限制。

经济成长要避免“岗位数 × 每人效率”同时增加后远远超过成本。以下系数已用于本轮自然经营模拟；结果和策略限制见实施记录：

| 项目 | 实施公式 |
| --- | --- |
| 每人产量 | 保留原基础产量与每级增加 2 的规则 |
| 一般升级木材 | 原基础费用 + 25n + 2n²，n 为当前等级减一 |
| 一般升级粮食 | 原基础费用 + 10n + floor(n² / 2) |
| 仓储 | 200 + 160n + 12n²，n 为修缮等级减一 |
| 住宅扩建木材 | 30 + 10n + floor(n² / 2) |
| 住宅扩建粮食 | 10 + 5n |
| 塔伤害和城门上限 | 保留现有二次等级战力，避免同时改写全部战斗机制 |

仓储增长必须能覆盖自身下一阶修缮费用，不能在某一级形成“扩仓的费用超过仓储，因此再也扩不了”的死锁。费用、产出和容量都沿用安全整数校验，不用 `Infinity` 或任意放行代替无玩法等级上限。

本轮模拟覆盖自然扩人口、限制人口以及主动使用战技的经营策略；固定偏科阵容和不同玩家的建设偏好仍需继续试玩检验。调节系数时保持此处明确的经济结构，不添加离线收益、自动生育、充值或隐藏补偿。

旧经营脚本限制最多十八人、四个孩子且只购买前四塔，只能作为旧策略对照。新增长线策略必须实际扩人口并购买第五塔，额外记录人口年龄构成、真实劳力、成年专长待选择数量以及等待下一次升级的夜数。现有手动成家、迎接孩子和成年专长选择暂时保留，不擅自改成自动执行。

## 6. 五塔防线

总塔位五个，初始箭楼与石塔不变，其余三个为空地基。第五位置优先放在道路后段左侧草地，与城门和路牌留开距离；具体坐标由三种塔最大占地和射程覆盖测试确定，不直接把第五塔塞到道路中央。

统一使用 `PADS.length` 驱动初始塔数组、蓄力、驻守、视觉池、技能光效和存档校验。朝向以所在道路侧决定，避免增加第五塔后仍只配置四项左右朝向。建设面板的驻守摘要 `/4`、玩法说明的“四个塔位”和模拟脚本的四塔循环一并改为统一数量。

需验证每个位置的三种塔都能攻击实际道路中的敌人，合计十五组；验证满级外观、短屏和长屏下不压道路、城门血量、路牌、文字或侧栏按钮。允许移动或减少阻挡第五塔的少量装饰树。

### 7.2 列表展示

已学会与达到学习波数的战技正常显示。判断必须保留“已学会”分支，不能因重开后的波数变低就隐藏已保留的技能。尚未到波数的战技只显示最近的一个未知条目，例如“未知战技 · 守住 12 波揭晓”。不展示其真实名称、图标、效果、费用，不提供进入真实详情的点击路径；更远的战技不占列表。

达到门槛后，未知条目变为真实技能，并显示下一张未知条目。材料不足时正常列出缺口。红点只针对已揭晓且能学习的战技，不为隐藏内容提前发红点。玩法说明、详情跳转和其他入口同步遮蔽未揭晓信息，不能只在列表盖一块问号。

## 8. 波次与长期难度

### 8.1 数量优先，控制同屏与每夜长度

保留前期辨认敌人、每十二夜首领和季节组合的基础。增加每夜总来敌数量，采用队列分批入场；保持同时在场的预算为 40，计划数组上限为 128。未出场敌人不能丢弃，不能因为达到同屏上限就提前宣布胜利。

数量曲线采用平滑增长项：`8 + floor(64 × (1 - exp(-(day - 1) / 72)))`，再叠加一轮十二夜内的轻重波动。常规波到后期约 70～80 只；通过刷怪节奏和阵容变化形成压力，不让后期一夜出现数千只、持续几十分钟。

阶段验收目标如下，具体人数会因轻重波和首领安排浮动：

| 阶段 | 每夜总数目标 | 主要压力 |
| --- | --- | --- |
| 1～12 夜 | 8～24 | 认识基础、快怪、重甲与第一个首领 |
| 13～36 夜 | 18～38 | 双批次、前后排组合，开始投资第五塔 |
| 37～72 夜 | 30～56 | 群怪和重甲交替，减速与范围伤害有价值 |
| 73～120 夜 | 45～68 | 阵容节奏、首领与护卫组合 |
| 更长期 | 约 60～80 | 数量趋稳，强度缓慢增长，组合继续轮换 |

### 8.2 个体数值

将原二次增长改为第十二夜后温和的线性增长，经20组种子和长线模拟，采用 `1 + max(0, day - 12) / 32`。保持快慢与护甲差异，速度不随波数无限增长。撞门伤害、门血、修门费用和技能一起测算，避免一只漏怪就突然秒门。

原因是人口有最终容量、升级成本采用二次增长时，长期设施等级的增长会减慢；若继续让敌人血量按夜数平方增长，最终仍会形成数学上必败的墙。敌人强度只取波数、挑战档和固定种子，不根据玩家刚刚升级的塔偷偷抬升。

保留自然的失败可能，不承诺任意操作都永远不失败。目标是合理经营能持续推进，偏科或不升级会遇到压力，玩家能从下一次建设或技能选择中获得明确改善。

- 不通过重复同一帧、单纯平移整图或左右镜像冒充新增步态。
- 动画进度以实际行走距离推进；冰塔减速、暂停、三倍速、出生点偏移和不同道路路线都保持步幅一致。固定战斗步累计前后 `enemyPoint` 的实际距离，不把出生偏移算成走过的路程，不让屏幕重排改变动画距离；死亡快照保留最后动作进度。
- 主体、脚点、头部与背部挂点逐帧记录。挂件随躯干，不能逐帧漂浮或穿进眼睛、武器。
- 保持同一套光源、相机与比例。帧间只变化动作，不重新缩放身体来填满裁框。

修改前资源校验明确拒绝多于四帧，并要求全部脚点是 `(48,92)`。必须同步修改原始制作配置、Laya 导出、运行时校验、资源合同和资源测试，不能只在图集中加入新图片。

### 9.3 阴影与接地

原图不烘焙落地阴影，运行时只绘制一次独立软影。每类记录稳定地面接触中心，行走帧记录实际支撑点与身体位移，不能把最前方抬起的脚尖当成统一脚点。

阴影中心、裁图偏移、画布与缩放必须在同一坐标体系中计算。双足与四足使用不同覆盖范围；同一身体的染色、翻转和大小变体共用这些坐标，不能在每次换帧时按整张 Alpha 包围盒重新居中。

验收需包含十类怪物全部帧、无配件与所有允许配件、最小/最大体型、道路转弯、受击红闪与死亡帧暂留；既检查单体放大对照，也检查游戏内实际尺寸。

## 10. 声音

增加约 0.09 秒的通用轻发射声，三类塔共用，目标不超过 2 KB。以一次真实发射轮次触发，不按每颗分裂弹重复叠加；同一现实时间窗最多播放一次，初值为 120 毫秒，防止三倍速五塔齐射变成刺耳噪声。

替换守夜背景为无鼓的小调拨弦和低音弦乐，约 16～20 秒循环，目标不超过 80 KB。单声道、22.05 kHz、32 kbps；曲谱、合成参数与生成脚本一并保留。日间音乐不改。

新增声音位于战斗分包，随怪物一起在入夜前准备完成。复用现有音乐开关、手势启动、切后台、音频中断、释放以及失败只提示一次的策略，不新增自动重试或强制开启声音。
