# 显示层职责整理

## 目标与范围

1.0.26 针对多轮增删功能后积累的显示层职责混杂进行整理。保持当前玩法、数值、随机抽样、存档格式、资源图片、画面布局及操作流程，配置版本仍为 18。本轮不重做此前已拆分的村务规则、面板或资源下载协调器。

实施前保存源码及编译基线，并由独立子 Agent 审核拆分边界；实施后再进行差异审核。生产源码共 91 个 TypeScript 模块，均可通过 Main 或 WechatBuild 的静态引用到达；这只证明模块有引用，不能据此推断每个导出都在运行中使用，因此未批量删除文件。

## 模块职责

| 入口 | 当前职责 | 后续修改应放置的位置 |
| --- | --- | --- |
| `view/VillageWorld.ts` | 世界节点、人物和建筑呈现、视觉时钟、深度排序及组件调度 | 地图生命周期及跨表现组件的顺序 |
| `view/WorldInteraction.ts` | 命中检测、遮挡、按下来源与目标身份、多指取消 | 地图点击行为；通过回调读取当前村庄和人物运动对象 |
| `view/ProjectileMotion.ts` | 既有弹道轨迹、到达与消失时间 | 纯运动计算；本轮不修改 |
| `view/ProjectileVisuals.ts` | 固定弹道节点池、主体和柔光绘制、每帧清空显隐 | 投射物显示；不推进战斗、不新增时钟 |
| `view/SpriteFrames.ts` | 分包读取、逐帧结构校验与贴图创建、缓存重试、提交及失败回收 | 资源生命周期与运行贴图访问 |
| `view/SpriteResourceValidation.ts` | 新建贴图之后的完整包合同校验 | 人物方向、动画、建筑及怪物挂点的合同规则 |
| `view/GameHud.ts` | 原 HUD 显示职责 | 移除未使用的私有资源持有，保留构造调用约定 |

地图类由 463 行降至 382 行，资源类由 161 行降至 115 行。拆分依据是手势状态、节点生命周期和资源合同边界，不以减少总行数为目标。没有增加通用管理框架、空转发层或零散单行工具。

## 保持的关键时序

- 地图先记录按下身份，再注册通用按钮点击；人物池整帧更新完毕后才取消失效手势。人物自身贴图和建筑全部部件继续采用各自原命中范围，地面可穿透、前景树木阻挡。
- 重开读取新的 `state` 和 `motion`，不会保留旧村民引用；销毁先取消触摸，再沿原 `GameView.root.destroy(true)` 回收节点和事件。
- 投射物每个池位仍按柔光、主体的顺序创建；每次渲染先隐藏全部池位，再填充当前弹道，包括无状态、无战斗及未加载资源的情况。
- 贴图逐帧检查与创建仍交错执行，之后才进入完整包合同校验。失败仍只销毁本次创建的纹理，保留有效 PNG 缓存，标记元数据重读；校验顺序和原异常文案不变。
- 玩法、配置（发布标识除外）、平台和存档源码与基线一致；运行图片、动画元数据和音频未改，不需要重新制作资源原稿。
