# 守村战技系统规划

日期：2026-11-14。修订：第二版，按用户最新四点要求重新规划。

状态：第二版方案已获用户确认，2026-11-14 开始实施 1.0.19。以下保留设计依据和约定；实际落地、验证及上传回执以 [41 战技系统实施与 1.0.19](41_战技系统实施与1.0.19.md) 为准。具体新增技能仍由用户另行提供。

## 1. 已确认方向与本轮边界

| 用户已明确的要求 | 本方案对应处理 |
| --- | --- |
| 守住波数解锁，消耗木材与粮食 | 波数开放学习资格；支付一次材料后学会。资格不等于已经获得 |
| 入口放在排行榜下方 | 地图左侧“排行 / 战技”上下排列，统一图标、文字与按压表现 |
| 不采用上一版技能，之后另行告知 | 删除上一版五个新技能、效果、波数和价格的正式提案；不把它们做成游戏内容 |
| 先把系统功能做好 | 规划配置、学习交易、携带、夜间使用、存档、面板、红点与测试接口；正式目录先只有已有“大王之心” |
| 出界面，全部规划 | 本文配合三栏效果图，展示入口、列表和详情；图中待定条目仅用于状态演示 |

“大王之心”保留开局自带、免费、每夜一次、攻速 +50%、持续 15 个战斗秒。它是当前已存在的战技，不属于被否定的五个新增技能。

本次设计建议继续使用一个携带槽位，白天免费更换，夜间固定。用户已经确认购买机制与入口；入口显隐、红点与传承细则是下文推荐方案，应随本设计整体审阅，不标为已经实施。

## 2. 工程依据与方案选择

### 2.1 已核对的现有实现

- `GameHud.ts`：排行榜当前在地图左上，`legacy.bestNight > 0` 时显示；现有按钮为横向图文。底栏白天是圆形守夜按钮与村务入口，夜间是暂停、技能和倍速。
- `NightControls.ts`、`GameSession.ts`、`BattleSimulation.ts`：大王之心已有资格预检、单次额度、持续计时与倒计时环。夜间换驻守及打开面板可保留同一战斗实例。
- `PanelContext.ts`、`PanelListOrder.ts`、`ScrollList.ts`：已有统一面板、滚动、进入时排序及返回状态，适合复用。
- `VillageRules.ts`、`GameSession.command()`、`SaveStore.ts`：已有纯规则候选、状态提交和保存失败处理，学习材料扣除与学会结果应走同一次提交。
- `Growth.ts`、`RuleConfig.ts`：仓储初始 200，民居修缮增加容量；资源不足提示和现有/所需显示已有做法。
- `ResourceManifest.ts`：冠心图标、金绿按钮、卡片、面板、粮木图标已在 base 中。卷轴入口图标是本轮设计新增，当前没有同名正式资源。

当前源码基线为 `main` / `46362ff5dbd948881b796981e102153600c4e343`，工作区有既有未提交修改；此记录只确定读过的上下文，不将 HEAD 当作包含全部当前代码的干净版本。

### 2.2 推荐结构

采用“一个战技列表 + 一个详情面板”。列表直接学习或携带，详情提供完整说明。两者共用规则和提交操作。

另一种可行结构是单个大面板同时放列表和详情，但竖屏下会挤压图标、材料行和按钮；拆出独立商店、背包、装备页又增加往返。本次按用户交由设计的方向采用前者，不增加独立商店、技能等级或新货币。

## 3. 入口、解锁与获取

### 3.1 地图入口

- “战技”固定排在“排行”下面，两个入口采用同一组紧凑徽章：图标在上、文字在下，图标与文字都放在按钮内部的安全区。
- 推荐沿用排行的 `legacy.bestNight > 0` 显隐条件：首次守住一波后一起出现；有最高纪录的重开村仍显示两个入口。首夜仍能从夜间主按钮使用默认大王之心。
- 这只是入口开放规则，不作为新技能学习资格。学习资格仍使用当前村庄 `completed`。
- 不再在小记增加重复主入口；战前确认保留“当前携带 / 更换”的就近入口。
- 按钮属于 HUD，不能参与地图深度排序。图标、文字与红点挂在同一按压容器中，沿用取消点击与音效逻辑。
- 初始试排可按 720 逻辑宽度下的约 104×104 徽章、约 12 间距开始；最终以可见边界和真实点击区为准，不机械套用当前 142×62 横向按钮尺寸。
- 必须核对短屏、长屏、三种塔及高阶塔 1：不能遮塔主体、塔名、道路或抢占塔的点击区。若试排重叠，先调整徽章的宽度、左边距与纵向位置；不能为入口擅自改塔位、射程或地图比例。

### 3.2 学习资格与支付

一个未学会战技必须同时满足：白天、当前成功防守波数达到该战技配置要求、木材足够、粮食足够、没有未结束的状态提交。

- 达到波数只变为“可学习”，不会自动发放，也不会自动扣资源。
- 点击明确写出费用的“学习并携带”，一次性扣木与粮，加入已学会集合并设为当前携带。
- 已学会技能不重复收费，换回时不重新检查解锁波数；使用技能也不收材料。
- 夜间可查看，不能学习或更换，包括手动暂停期间。
- 新技能的解锁波数、价格与效果全部待用户给出后配置；不把上一版 3/6/9/12/18 波及价格自动沿用。
- 图稿的“待定战技 A：3 波、40 木、10 粮”和“待定战技 B：9 波”仅为展示状态的示例，不进入正式技能目录。

## 4. 界面设计

设计稿：[守村战技界面方案](../../res/design/tactics/01_守村战技界面方案.png)。它是设计效果图，不是实际游戏截图；上方三栏名称是设计说明，不是游戏内新增导航。

### 4.1 战技列表

绿色标题“守村战技”，右上关闭；下方显示当前已守波数、木与粮，再显示“每夜携带 1 个 · 使用 1 次”。列表上下滚动，不做翻页或无必要的分类页签。

每张卡片包含：左侧大图标，中间名称、短效果、学习条件与材料行，右侧明确动作。当前携带用金边和“已携带”；材料满足的待学习卡片用绿色按钮；未达波数或材料不足用灰绿状态，文字仍保证对比度。

进入时排列：当前携带 → 可立即学习 → 其他已学会 → 波数够但缺材料 → 波数未达。同组按配置排序。打开期间状态与材料实时更新，但条目身份顺序不跳动；重新进入时再排序。

点卡片正文打开详情，点按钮执行操作；事件不能冒泡成先支付再打开详情。拖动滚动列表不触发学习。已携带状态不可卸下，保持始终有一个有效战技。

正式首版目录只有“大王之心”时使用紧凑面板高度，最多只绘制这一张卡片与简短规则，不放“待定战技”、虚假锁位、不可用技能或大块空白。多条目的完整布局用测试夹具验收。

### 4.2 战技详情

采用适中高度的奶油内容面板。标题居中，右上关闭；从列表进入时左上返回，保留列表滚动位置和进入时排序。直接从战前打开详情时保存对应返回来源。

- 图标、名称、短说明垂直居中。
- 已学会战技显示效果、限制和当前携带状态，不再把价格作为主信息。
- 未学会战技显示学习波数、木粮费用、现有数量及支付后余额。
- 底部一个主按钮：“学习并携带”“携带”“已携带”或明确的灰态原因。
- 详情内容多时正文滚动，主按钮固定；不能把整个弹层做得比安全区还高。
- 关闭返回地图，返回按钮回上一层；整个面板链共用暂停生命周期，不能在详情切回列表的瞬间恢复战斗。

### 4.3 条件状态与文案

| 状态 | 显示方式 | 操作 |
| --- | --- | --- |
| 未达到波数 | “已守 6/9 波，还需 3 波” | 学习按钮灰色，可查看详情 |
| 波数达标、木不足 | “木 20/40”，缺口红色，“还缺 20 木” | 不扣资源 |
| 波数达标、粮不足 | “粮 5/10”，缺口红色，“还缺 5 粮” | 不扣资源 |
| 两种材料都不足 | 分别标红，详情完整写明两种缺口 | 不把一半材料先扣掉 |
| 费用大于仓储容量 | “先修缮民居，当前仓储 200” | 沿用现有仓储前置提示思路 |
| 满足条件且未学会 | 清楚展示费用，绿色“学习并携带” | 一次提交学习和装备 |
| 已学会、未携带 | “携带” | 免费更换 |
| 当前已携带 | 金色勾选、“已携带” | 不重复提交 |
| 夜间 | “天亮后可学习 / 更换” | 只读查看，不因暂停而开放换装 |
| 保存中或保存失败待处理 | 沿用已有保存阻断与错误处理 | 不重复扣费，不假报成功 |

多项条件同时不满足时，操作资格按“时段与提交状态 → 波数 → 仓储容量 → 木粮缺口”给主要原因；材料行仍可同时显示完整数量。图稿中的斜杠数字均为“现有/所需”，不是分数运算。

### 4.4 红点

推荐使用现有“可操作提示”逻辑：白天有任一未学会、已达波数且木粮足够的正式战技时，地图战技按钮显示红点；学会或资源变得不足后消失。仅能切换已学会战技不亮红点，夜间也不亮购买红点。

红点不是“看过就消失”的消息通知，因此不新增已查看记录。其判定与学习按钮使用同一个预检结果；不能为显示红点发起下载、扣费或保存。

### 4.5 图文与适配要求

- 延续明亮田园：森林绿标题、嫩叶绿内底、奶油金边卡片、绿色操作、灰绿禁用、棕色正文、红色不足。
- 图标按可见边界居中，不按透明母画布盲目定位；同类图标视觉大小一致，数字基线对齐。
- 逻辑字号初稿：面板标题 34～36，卡片名称 30～32，正文 26，辅助 24；长数字使用项目现有简写，并校验缩小后的可读性。
- 名称、费用和按钮预留各自区域，按钮至少留出约 12～16 逻辑像素内边距；不通过把两行文字压进短按钮解决布局问题。
- 320×568、375×812、390×844、430×932 等代表窗口检查安全区、可视卡片、滚动与按钮；最终结论以实际 Laya / 微信绘制为准，生成图不代替设备适配验证。

## 5. 战前、夜间与返回流程

战前确认增加一行“今夜携带：大王之心”，右侧“更换”。从这里进库，学习或切换保存成功后直接回战前，更新技能摘要，不替玩家立即开始守夜。

从地图进入的列表直接操作后更新当前条目与材料，保持列表开启；从详情执行成功则回来源列表并恢复滚动。这有别于旧稿中“学习后强制返回小记”，旧路径不再使用。

确认开始守夜时，携带 ID 写入本夜战前快照。夜间圆形按钮、状态栏和倒计时读取该快照对应的配置，不能在多处硬编码显示“大王之心”。第一阶段实际战斗仍只有现有的大王之心效果。

本次保持已有大王之心触发资格，不额外加入“场上无人时不能施放”等上一稿新规则。其攻击加成、持续时间、倍速和暂停语义全部保持。未来技能的目标条件、即时/持续形式及战斗反馈等由用户确定效果后逐项实现。

同一战斗实例中打开列表、查看详情、返回、夜间换驻守、切倍速及前后台切换，都不得重置使用次数或剩余时间。关闭游戏后读取夜晚，沿用当前从战前重打整夜的规则，队列与技能使用状态一起恢复，不单独刷新技能。

## 6. 配置、状态与原子交易

### 6.1 配置边界

建议独立 `TacticConfig`：每项显式定义稳定 ID、展示顺序、名称、图标、短说明、详细说明、所需成功波数、木材费用、粮食费用和已实现的效果标识。字段名为实施建议，不视为现有 API。

展示和价格不散落在面板或战斗代码里；村民的 `skill` 仍表示个人专长，不能混用类型。注册校验拒绝重复 ID、非法/不安全数值、缺图及尚无实现的效果标识。未知技能不能悄悄按大王之心执行。

第一阶段正式配置只登记“大王之心”：初始已学会、初始携带、学习成本 0；只接入现有效果。未来新增技能需要同时具备用户确认的数据、资源和具体效果实现，单纯添加任意配置不代表任意战斗能力都可运行。

### 6.2 存档最小数据

推荐新增一个战技状态，包含“已学会 ID 集合”与“当前携带 ID”；夜间快照另含本夜使用的 ID。学习资格由当前成功波数和配置推导，不另存一份易失配的资格列表，也不存红点、按钮灰态或已查看状态。

游戏初始化显式设定默认大王之心。保存校验核对 ID 已登记、已学会去重、携带属于已学会、本夜快照合法；错误走现有存档异常路径，不静默替换或发放。

结构变更时按现有配置版本规则升版，研发验证先备份再清档；旧版读取沿用既有不兼容处理，不新增迁移、不无提示地清除玩家存档。当前规划不修改配置版本或实际存档。

### 6.3 学习与换装提交

1. 点击时用最新状态重新预检，不信任绘制时捕获的旧资源或资格。
2. 同一候选状态中完成扣木、扣粮、加入已学会及更新携带；两种材料与学习结果必须一起提交。
3. 提交中锁定相关操作，连续点击不能创建第二笔扣费。
4. 保存成功后才显示“已学会 / 已携带”和新资源；保存失败沿用既有阻断与重试，不添加独立重扣费机制。
5. 免费换装也通过同一现有提交入口；重复选择当前战技不创建无效保存。

不额外增加“购买后必须剩够今晚口粮”的阻断规则。详情展示支付后余额供玩家判断，是否学习仍由玩家决定。

## 7. 重开规则建议

| 场景 | 推荐处理 |
| --- | --- |
| 正常读档 | 保留已学会和当前携带 |
| 达到新波数 | 更新学习资格；未支付的不发放、不扣费 |
| 本夜失败 | 不增加波数，不新开学习资格 |
| 传承开村 | 保留已学会集合，默认携带大王之心；未学会项目按新村成功波数重新判断资格 |
| 纯净开始 | 清空购买结果，恢复仅大王之心；最高排行榜纪录按既有规则保留 |
| 历史最高纪录较高 | 可以沿用已开放的侧边入口，但不能代替本村的学习波数 |

传承保留已学会集合是本系统新增的推荐规则；它不改动既有人口、粮木、每日口粮、家谱与天赋的重开政策，也不将用户确认购买机制解释为已经确认了全部传承细则。

## 8. 资源与包体

效果图和提示词放在 `res/design/tactics/`，明确标注不进入运行包。正式制作时，卷轴图标的源文件、采样配方、派生图片、图集与资源台账一起更新，不从整张设计图硬裁按钮或文字进游戏。

- 入口需要一张独立的小卷轴图标；卡片、面板、按钮、资源符号和大王之心图标复用现有 base 资源。暂不制作未知新技能的图标或特效。
- 入口卷轴属于主包，因为进入村庄后要直接显示；不能放到尚未下载的战斗包后再用错误图标顶替。
- 当前只有大王之心，打开战技列表不需要下载 battle；守夜前的现有资源加载和手动重试保持原规则。后续新增技能的图标、特效与资源依赖需按实际内容再规划，不能为占位项提前下载全部怪物。
- 第一阶段不增加分包、不恢复粒子。新图标派生先以约 96～128 像素试验清晰度；体积需实际测量，不承诺压缩后的固定大小。
- 当前 1.0.18 本地主包 4,172,972 字节，距 4 MiB 仅 21,332 字节；新增图标与代码都计入预算。先完成最小工程与包体试验，若超额须出代码拆包或已有冗余优化方案再确认，不能削减既有画质或暗删功能来硬塞。

## 9. 实施拆分与验收

本节为已确认的实施清单；完成记录见 41 号文档。

| 阶段 | 工作 | 验收重点 |
| --- | --- | --- |
| 1. 通用状态与规则 | 配置、已学会与携带状态、资格、费用、原子提交、重开策略 | 双击只扣一次、材料一起扣、波数边界、保存失败、旧档处理 |
