## 设计基准

- UI：象牙白底、细琥珀边、深胡桃文字、森林绿主按钮，紧凑顶部、居中标题、左侧小记、无独立框的资源栏。
- 角色：圆润清晰的模型轮廓，区分年龄、职业动作和成人性别；不以几何占位模型替代最终设计。
- 怪物：沿用 5 种小怪和 5 种首领，模型、颜色和配件组合，不增加或变更战斗数值。
- 建筑：独立 prefab；用平台、石基、屋顶、梁柱与武器模块表现升级，保留可编辑源。
- 场景：同一正交视角和深度关系。真实模型的草、道路、树与花果属于场景，UI 标签与按钮仍为高清 2D。

## 技术路线与取舍

已比较局部 3D 桥接、整村 Bridge 和完整 Scene3D。全场景改造采用单个 Scene3D、正交 Camera 和原有 2D UI。所有世界实体共用深度缓冲；不再以图片 zIndex 模拟实体遮挡。无需引入物理或 NavMesh，也不为每个人物创建独立 RenderTexture。

GameLayout 继续负责 720 逻辑宽度、安全区、道路与居民区显示映射。原逻辑点先映射为屏幕点，再由 Camera 射线与地面求交转为世界坐标。模型头顶、发射口与建筑标记通过相机投影回 UI。全窗口视口先行验证，防止再乘 DPR 或非零视口偏移造成漂移。

保持现有 GameSession、VillageRules、BattleSimulation、VillagerMotion、ProjectileMotion、CombatPresentation 的业务语义、调用顺序和随机流。外观不参与伤害、射程、寻路或资源结算。

### 正式导入与发布链

Laya 编辑器中通过 `Editor.scene.createNodeByAsset` 创建导入模型，配置默认 idle，逐个 `createPrefab` 保存；`IEditorEnv.ExportAssetTool` 导出原生网格、材质、纹理和动作依赖。不能用运行时临时实例保存代替：试验中会丢失动作子资产引用。

```bash
node res/tools/build-world3d-resources.mjs \
  --native /Users/happyelements/Downloads/daidai-3d-implementation-20261113/native3d/export \
  --work /Users/happyelements/Downloads/daidai-3d-implementation-20261113/resource-build \
  --sync
```

新构建生成 manifest v4、运行白名单和代码端 `ResourceManifest.ts`，再同步到 Laya 游戏工程。只有白名单资产进入微信导出目录；GLB、Blender 工程、原始参考、旧像素动画、验证脚本均不进入游戏包。旧 `build-resources.mjs` 检测到 v4 时拒绝执行，避免下一轮误把运行资源覆盖回序列帧版本。

加载器只接受正式原生 `.lh`。人物/敌人必须实际具备蒙皮渲染器、网格、材质及要求的动作；3D 粒子必须具备对应原生渲染器。读取成功但内容不完整也记录失败 URL，玩家下次手动重试绕过该坏缓存；不改变现有分包时机和单任务规则。
