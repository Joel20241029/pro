# 代代守村：组合怪物与分阶段资源加载

日期：2026-11-12。状态：用户已确认并完成实施；代码回归、Laya 实绘、微信开发者工具运行和三包导出通过，真机网络与帧率待测。

## 1. 已确认需求与本次目标

- 小怪基础造型总数达到 5 种，Boss 基础造型总数达到 5 种；包含现有可复用底型，染色变体不单独计入基础造型数量。小怪数量按用户最新要求从 10 种缩减为 5 种。
- 题材采用用户确认的“山匪＋山林异兽”。保持现有像素画、林间道路和村落的整体风格。
- 使用底型、局部染色、可替换配件和受控缩放组合怪物，运行中持续生成不同组合，不为每个组合绘制整套图片。
- UI、基础地图与建筑放在主包；村民放在独立原生分包；小怪和 Boss 放在另一个独立原生分包。
- 主场景先出现，然后加载人物；人物资源完整准备好才显示人物。失败时玩家可以主动重试。
- 点击“开始守夜”时准备怪物资源；失败可以再次点击，不进入缺资源的战斗。
- 同步维护设计、代码、可编辑原始资源、制作配方、分类说明、图集和微信导出，仍导出到 `tryVersion/wxgame`。

“无尽”采用有限素材形成大量可重复组合，并持续生成波次；不承诺有限资源能够生成数学意义上永不重复的独特怪物。颜色、配件数量和每个底型的兼容范围会限制实际组合数。

## 2. 当前实现与改造依据

检查基线为 `main` 的 `f3ccb8d`，检查开始时工作区干净。LayaAir 版本为 `3.4.2`。

| 当前实现 | 证据与影响 |
| --- | --- |
| 4 种小怪＋1 种匪首，各 4 帧行走 | `DefenseConfig.ts`、`res/animations.json`；实际底图包含拟人化山林敌人，可继续保持这一画风 |
| 所有资源位于 `resources/village` | `BuildSettings.json` 只有一个非自动加载的本地原生分包 |
| 地图、人物和敌人共享 `world_0.png` | `build-resources.mjs` 按 world/ui 两组打包，单纯移动文件不能实现按时机下载 |
| 等全包加载完才创建村庄 | `Main.onStart` 先等 `loadPackage` 和 `SpriteFrames.load`，最后创建 `GameView`；等待期间背景为绿色 |
| 失败要求重新打开游戏 | `Main` 的错误分支没有玩家主动重试入口 |
| 角色相关界面会立即读取图集 | `VillageWorld.render`、人物详情、旅人选择等都调用 `frameId/get`，必须共同受资源就绪状态控制 |
| 基础场景构造时已读取人物效果图 | `VillageWorld` 构造函数给人物池绑定 `fx_hearts`；分包后不可仅在 render 中判断就绪，构造阶段也必须延后此绑定 |
| 守夜确认会立即结算资源 | `VillageRules` 的 `NIGHT` 命令自动分配驻塔、计算粮木并切到 `NIGHT`；资源等待必须放在此命令之前 |
| 重进夜晚从该夜开头重打 | `GameSession.accept` 根据夜晚快照创建 `BattleSimulation`；资源未就绪时必须暂停，不能偷偷推进 |
| 首领与扰阵行为直接判断怪物 ID | `BattleSimulation` 的 `enemy_chief` 召唤和 `enemy_disruptor` 扰阵需改为有明确配置的能力 |
| 原生编辑器资产已有可复用流程 | 建筑采用独立 `.lh`、`.mc`、严格转换、运行布局和图集；怪物编辑流程复用这一制作约定 |

改造前目录原始字节为 3,476,918，主包 1,651,835，现有资源分包 1,825,083。当前 `world_0.png` 为 1024×1024、1,331,715 字节；`ui_0.png` 为 512×512、114,881 字节。原始目录字节不等于微信上传压缩统计。

## 3. Laya 能力核实与技术选择

核实来源包括工程自带 `engine/types/LayaAir.d.ts`、本机 IDE 的 `engine/libs/laya.core.js`、`laya.adapter-weixin.js`，以及官方文档。

| 能力 | 已核实支持 | 本方案用法 |
| --- | --- | --- |
| 图片着色 | `Graphics.drawImage`、`drawTexture` 有 `color` 参数；本机 DrawImageCmd 将颜色传入纹理绘制 | 中性明暗的可染色层使用颜色相乘，不假定普通 Sprite 存在可直接使用的 `color` 字段 |
| 色相、饱和度、亮度矩阵 | `ColorEffect2D` 有对应方法；旧 `ColorFilter` 被标记为 deprecated | 可用于样片对照；首版以局部着色为主，逐个怪物的后处理成本先实测 |
| 叠加、镜像、缩放、旋转 | Sprite 容器、`scaleX/scaleY`、旋转和层级 | 装备、头饰、背饰以子层组成一个怪物，整体镜像和足底排序 |
| 时间轴动画 | 已使用原生 `.mc` 与 2D 动画组件 | 行走继续以 2～4 帧为主；必要配件微动由编辑器保存动画，复用战斗时钟 |
| 原生分包 | `loadPackage(path, onProgress)`，本机返回 `Promise<boolean>` | 继续使用已有 Laya 原生分包通道，失败同时检查 false 和异常 |
| 下载与素材就绪是两步 | 微信适配器先调用原生 `loadSubpackage`，Laya 再注册 `fileconfig.json` | 之后还须读取、校验图集、帧表和动画，不能把原生下载成功当作可开战 |

方案比较：

1. 每种变体输出完整序列帧：直观，但素材随颜色与配件的组合数量相乘，不符合本次资源目标。
2. 整图矩阵滤镜换色：改动少，但脸、装备和描边同时变色；大量实例的后处理还需性能核验。
3. 中性身体层＋原色细节层＋兼容配件：推荐。底型的轮廓差异明确，着色只作用于指定区域，复用现有帧动画、图集和编辑器制作方式。

第三种为本次已采用方案。先完成小样验证再制作；不把“接口存在”表述成“微信真机表现已经通过”。

- [ColorFilter 与 3.4 弃用提示](https://layaair.layabox.com/3.x/api/3.4/classes/laya_filters_ColorFilter.ColorFilter.html)。
- [时间轴与 Animator2D](https://www.layaair.com/3.x/doc-en/IDE/animationEditor/timelineGUI/readme.html)。
- [通用发布、资源包含与分包](https://layaair.com/3.3/doc/released/generalSetting/readme.html)。
- [Laya 官方微信分包流程](https://layaair.com/3.2/doc/released/miniGame/wechat/readme.html)。旧文档示例需结合本机 3.4.2 的 boolean 返回值使用。

以下名称、解锁与战斗定位已获用户确认。造型通过引擎小样验证后展开，性能和战斗系数在模拟中调平。

| 小怪底型 | 造型差异 | 战斗定位 | 首次可出现夜晚 |
| --- | --- | --- | ---: |
| 山匪 | 轻装短刃、现有底型 | 基础单位 | 1 |
| 疾行匪 | 瘦长身形、短披巾 | 低血快速 | 2 |
| 甲兵 | 厚甲、宽肩 | 高甲慢速 | 4 |
| 野猪 | 低重心、獠牙 | 慢速厚血、撞门较重 | 6 |
| 扰阵师 | 现有法器与长袍 | 沿用扰阵减攻速 | 7 |

小怪名单保留现有 4 种底型，并增加四足野猪：继续覆盖基础、疾行、护甲和扰阵定位，新增厚血撞门型与明显不同的身体轮廓，控制新增制作量。5 种指基础类型数量，同屏敌人容量与波次人数仍按现有规则配置。

| Boss 底型 | 造型差异 | 主要战斗辨识 |
| --- | --- | --- |
| 山寨匪首 | 复用现有魁梧拟人底型、冠饰 | 沿用定时召唤山匪 |

| 獠牙兽王 | 宽体巨兽、明显獠牙 | 厚血与较重撞门伤害 |

Boss 出场节奏保持每 12 次守夜一次。前 5 次 Boss 战按上述顺序展示不同底型，后续循环底型并变化合法外观组合；第一场仍为原匪首。每波基础 Boss 数保持 1，召唤与同屏上限沿用现有边界。若后续需要更频繁的 Boss，应作为独立难度变更讨论。

## 5. 可组合外观与确定性

每个实例由以下内容描述：基础底型 ID、身体配色 ID、细节/纹样 ID、兼容配件 ID、受控体型档和外观种子。

- 基础底型提供实际轮廓与行走姿态。每个底型单独制作预制体，不把 10 类放入一个总预制体。
- 配件按人形、四足、宽体等骨架族声明兼容范围、挂点与前后层，不把人形头盔强塞给野兽。
- 同一角色的所有帧共用原始画布、足底 pivot；配件挂点以未裁边画布定位，不能用每帧裁剪后的左上角定位。
- 染色层使用中性色明暗，脸、眼、牙齿和需要保留的描边/材质细节采用原色层。原有彩色底图不直接承诺能乘色得到任意新颜色。
- 小怪初步控制在 3～4 个实际绘制层，Boss 在 5～6 层以内。节点/绘制命令复用；角色出生或外观改变时配置颜色和部件，不在每个逻辑步重新创建滤镜、纹理或随机外观。
- 外观结果在生成波次时锁定，种子与波次一起保存；召唤单位从父怪物种子与召唤序号确定派生，重试和重进不会重新抽签。
- 外观随机不消费生育或经营随机序列。战斗属性根据底型与现有波次词缀决定，配饰数量和随机色不隐式改变伤害。
- 疾行、重甲和扰阵等定位有稳定的轮廓标识；纯装饰颜色不暗示实际不存在的燃烧、中毒等能力。
- 小怪与 Boss 的最大可见范围、镜像、范围框、脚底和血条挂点参与实际道路预览，防止变大后挡住塔标、城门或越出地图。
- 保持同屏敌人 40、计划单位 80、战斗效果 32 的现有容量边界；无尽波次不等于不断积累节点、纹理或敌人数量。

每一套新造型须检查左右转向、四帧逐帧对齐、受控缩放以及与道路两侧建筑的遮挡。

## 6. 三个资源归属

| 包 | 建议目录 | 内容 | 首次准备时机 |
| --- | --- | --- | --- |
| 主包 | `assets/resources/base`，不声明为分包 | 引擎与代码、UI、图标、基础地图、森林与装饰、全部建筑部件及建筑动画、日间音乐与点击音 | 启动即有本地文件，先完成本地解码与场景显示 |
| 人物分包 | `assets/resources/characters` | 成人、孩子、婴儿、老人、人物帧表、方向表、红心和表情 | 主场景显示后自动准备 |
| 守夜分包 | `assets/resources/battle` | 5 类小怪、5 类 Boss、颜色/配件表、敌人动画、箭石冰弹道与命中特效、夜战音乐 | 点击“开始守夜”；夜晚存档恢复时也必须准备 |

所有 UI 图标，包括村民、家庭、弓箭和石头的按钮图标，都属于主包；它们与世界中的人物立绘、弹道图不是同一资源用途。建筑升级和发射的原生动画留在主包，实际弹道在守夜包。

图集必须按资源归属重新打包，帧表和动画表也分别输出。不能沿用包含人物/敌人的混合 `world_0.png` 来假装拆分。包与包之间不引用另一个未加载分包的纹理、UUID 或动画；共享小资源由主包唯一持有，不复制多份。

`BuildSettings` 配置人物和守夜两个 `autoLoad: false, remote: false` 的原生分包。主包资源采用 Laya 的 resources 包含规则，并通过实际 `fileconfig.json` 与出包文件校验确认动态资源都被包含。继续由微信原生分包分发，首版不新增远程资源服务器。

## 7. 玩家看到的加载流程

### 7.1 首次进入与人物准备

1. 在 Laya 可控制的最早启动阶段显示与游戏一致的暖色底和简短准备提示，避免等待期间只有整屏绿色。
2. 只读取本地基础资源，显示完整地图、建筑与 UI。该步骤完成后才发起人物分包准备。
3. 在主场景中显示小型状态卡“村民正在到来…”。人物与人物头像暂不显示，交互与业务推进保持暂停。
4. 下载并注册人物包，再加载、解码、校验全部必需帧和动画。整包可用后一次性发布到资源仓库，显示人物。
5. 恢复正常开村、每日口粮、欢迎回来、清晨选择等已有面板优先级。不会因为加载完成而额外领取奖励、推进日历或清除手动暂停。

人物失败状态显示“人物资源未准备好，检查网络后重试”及“重试下载”按钮，地图和 UI 保持可见。每次点击只发起一次当前准备任务；失败不创建缺图人物，资源准备本身不生成业务命令、奖励或新结算。已有存档检查、清晨内部 FINALIZE、纯净开局中断后的同一候选补写仍可正常完成，不能把这些存档流程当作资源重试副作用而阻断。

人物准备期间，包括旅人头像、村民详情、家庭和名册在内的相关界面统一等资源就绪，不能只保护地图人物循环。`GameView/VillageWorld` 的构造、池预热、resize/reset/sync 同样只允许读取已就绪包；人物、红心、表情及其输入池的纹理绑定延后至人物包完整就绪，守夜特效池延后至守夜包就绪。不可见节点也不能提前读取缺失纹理。

### 7.2 点击守夜

保留现有战前确认操作，在点击首页“开始守夜”打开战前面板时触发守夜包准备。

- 准备中：显示“守夜资源准备中…”，确认按钮不能提交 `NIGHT`；来敌文字与粮木预览可显示。
- 准备成功：按钮恢复“确认安排 · 开始守夜”。玩家确认后走原有一次资源结算、一次战前保存、再开战流程。
- 准备失败：同一位置显示“重试下载”。玩家也可以关闭面板，稍后再次点“开始守夜”。此时村庄仍处于原白天，不扣粮木，不重抽波次，不推进年龄。
- 面板关闭或切后台后任务成功：只记录资源已准备好，不自动开战，不自动关闭其它面板，不播放夜战音乐。
- 已就绪：当前进程直接复用。再次启动时仍走微信原生包加载/校验入口，是否实际联网由微信缓存决定，不承诺永久离线缓存。

只有下载到本地、注册、必要资源解码、帧与部件依赖校验都通过，才允许提交守夜。

### 7.3 夜晚存档恢复

本地地图先显示；为会话设置专门的资源等待暂停原因，然后加载已保存状态。人物包和守夜包分别准备，全部就绪前不推进 `BattleSimulation`。

保留现有“从这夜开头重打”的存档语义，不新增战斗中途快照。资源就绪后按已有每日口粮/欢迎回来顺序让玩家继续；资源失败时在主场景内重试，不能退成白天、重新结算资源或重抽敌军。

### 7.4 失败、慢网与重复操作

以下失败、慢网与重试规则已随本方案获得用户确认：

- 包加载返回 false、抛异常、必要文件为空/解码失败、依赖校验失败：进入明确错误状态，只在玩家点击后重试。
- 主包本地准备失败：显示基础文字和可点击重试控件，重做本地准备；没有可用 UI 图片时以基础绘制构成同风格提示，不创建业务场景。
- 前台连续 30 秒没有加载进展：显示“下载较慢，请检查网络，正在继续等待”，保留地图和当前唯一准备任务。后台期间不计慢网时长，不将慢网假判成失败，不自动重试；战前面板可关闭，重开后连接同一任务。
- 现有原生加载通道没有已核实的取消接口；未结束的包请求按包名复用，不因为点击或慢网提示而叠加原生请求。收到明确 fail/false/异常，或加载结束后发现素材错误，才开放新一次重试。请求代号只约束应用层晚到结果，不能宣称阻止 Laya 内部的 fileconfig 注册。
- Laya 会将部分失败内容以 null 缓存。失败重试需对本包失败 URL 使用已核实的 `ignoreCache` 加载选项或精确清理失败缓存，不能只原样再调 load。成功缓存可复用，不清空整个 Loader；`ignoreCache` 也会合并到同 URL 的未结束任务，必须先收齐旧尝试的全部资源加载结果。
- 已就绪包保持就绪。子纹理在必需父图与配置全部成功、校验通过后创建并原子注册；失败的临时子纹理和表正确回收。已成功解码的包内父图按明确所有权保留供重试复用，不误销毁主包或其它包资源。
- 场景销毁、新村切换和后台返回都检查请求代号、当前会话身份与生命周期状态；晚到结果不得写已销毁节点、替换新村 UI 或重复提交命令。
- 使用“下载中／整理素材／已就绪”的阶段文字。本机适配器原生进度是 0～100，之后文件读取回调口径不同，首版不混用为虚假百分比。

## 8. 代码分工与配置边界

新增或扩展模块应有单一职责，配置与规则分离，不把全部流程塞进 Main 或 VillageWorld。

| 模块 | 责任 |
| --- | --- |
| `EnemyConfig.ts` | 10 种敌人的类别、名称、解锁、成本、数值和已支持能力；塔位与塔配置继续留在 DefenseConfig |
| `EnemyVisualConfig.ts` 与制作生成数据 | 配色、合法部件、骨架族、挂点、尺寸边界；不把编辑器权威布局再手抄一份 |
| `ResourceConfig.ts`＋生成的 `ResourceManifest.ts` | 三类包的路径、准备清单、资源归属、慢网提示阈值和预算的明确语义 |
| 资源准备协调模块 | 主包/人物/战斗状态、单次任务、主动重试、晚到结果处理；与 GameSession 保存重试分开 |
| `SpriteFrames.ts` | 由一次全量加载改为按包原子注册；统一 get/frameId 和足底恢复，保留缺失资源显式报错 |
| `EnemyVisuals.ts` | 怪物多层绘制、帧挂点、局部染色、部件池、尺寸与可见范围 |
| `WaveGenerator` 与存档校验 | 新底型抽取、Boss 轮替、外观种子、成本一致性与合法组合校验 |
| `BattleSimulation` | 从配置读取既有召唤/扰阵等能力，保留固定步长与有界队列 |
| `Main`、`GameView`、`GamePanels` | 首场景显示、资源状态卡、人物界面就绪限制、守夜前置检查 |
| `GameSession` | 独立的资源等待暂停原因与 NIGHT 提交保护；资源等待不属于存档保存失败，不能阻止已有清晨内部 FINALIZE 与保存恢复 |
| `WechatMusic` | 日间/点击主包路径与夜战包路径分别配置，资源未就绪不切到夜战音源 |

玩家交互在资源等待层统一禁用；GameSession 的资源暂停控制战斗 update，并在提交 NIGHT 前检查就绪，不能把暂停误用为禁止所有内部 command。现有 accept 在清晨无选择时会内部 FINALIZE，存档核对也可能内部继续，必须保留这些处理；所有人物相关面板等资源就绪后才绘制。

存档新增外观描述与敌人 ID，升配置版本，不增加旧档迁移。按既有开发约定交付后人工清理本地开发存档；微信云端最高守夜纪录继续保护。用户已确认的日历、人口、繁衍、每日口粮、排行榜计分和失败重开规则不在本次调整范围。

战前面板目前将全部类型拼成一行；类型增至 10 后改成紧凑的可滚动来敌条目，只列本夜实际来敌，并显示数量和定位。资源准备中使用主包文字与通用图标，准备好后可显示对应缩略图，避免提前读取战斗图集。

## 10. 体积与性能预算

旧的 3,500,000 字节内部总预算仅余 23,082 字节。增加底型并拆开图集可能增加元数据、包头和纹理空余区域，不能宣称分包本身会缩小总量或降低峰值内存。

已确认的内部预算：主包不超过 3,000,000 字节，人物包不超过 900,000 字节，守夜包不超过 1,100,000 字节，完整导出不超过 5,000,000 字节。这是项目工程预算，不是微信平台公布的限额，也不是当前已经完成的测量值。任何突破预算的方案需重新说明原因。

图集页从小尺寸向上选取，不机械为每个分类分配满幅大图。仅创建角色本次所需绘制命令和部件；不缓存所有外观组合的整张 RenderTexture。

首次加载的峰值内存、解码时间、40 敌人＋20 村民＋4 塔＋3 倍速下的绘制批次与帧时间需要实测。目标在目标手机持续运行时稳定达到至少 30 FPS、无增长型纹理/节点积累；以基线对照记录具体值。iPhone 12 是已有问题机型，优先验收；开发者工具的通过不替代真机。
