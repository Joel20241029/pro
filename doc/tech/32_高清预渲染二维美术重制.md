# 高清预渲染二维美术重制

日期：2026-11-13。状态：子代理可行性审核已完成，用户已确认按方案开始正式制作；先做 Laya 动态小场景，达到原参考图标准后扩展全量。目前仍未替换运行资源，不能将本文件视为美术达标证明。

## 1. 唯一验收基准

使用 [用户确认美术基准](../../res/design/hd2d/00_用户确认美术基准.png)。该图的左侧游戏画面决定实际显示比例、材质、草地、阴影与 UI；右侧单体放大图决定造型细节。不能仅参考配色、继续使用像素图或低精模型，也不能以技术测试通过代替视觉验收。

用户允许塔位不一致、二维角色视角较少，以及建筑静态底座采用整图；没有允许降低人物、怪物、建筑、地面、阴影或 UI 的精细度。老人、孩子共用各自一套性别中性外形和动作，这是用户明确要求，优先于参考图带胡须的老人。全部粒子效果移除。

用户后续确认：道路必须圆润连贯，程序绘制不能达到参考质感时允许独立道路图片；“数据”指尺寸、位置、占地和遮挡，玩法数值保持。全部怪物和首领只需正面略俯视视角，不出侧面、背面；仍保留 2～4 帧移动动作，行走不随道路转向翻转光照。

## 2. 已检查的现状

- 当前工程恢复为 Laya 3.4.2 二维图集，逻辑宽度为 720；`SpriteFrames` 已处理原画布、透明裁边、共同足底和序列帧。原人物、怪物帧及像素建筑不能满足新标准。
- `BuildingVisuals` 已支持七类独立建筑、等级和房数变体、攻击动画、视觉范围、占地、排序和发射口，适合改成完整底座加少量活动件。
- `GameLayout` 处理真实窗口、微信胶囊及安全区；`VillageScene` 和导航共享建筑占地。保持逻辑道路、塔位、射程与业务数值，调整表现布局须同步站点和遮挡。
- `UiSurface`、`UiGlyphs` 当前由代码绘制，清晰但造型过于简化；要达到参考图，需要精绘皮肤与立体小图标，不能只加粗描边。
- 当前六种粒子由 `ParticleLibrary`、`WorldParticles`、`ButtonParticles` 接入，三包都要求 `particles.json`，构建检查还要求粒子模块。移除须覆盖代码、契约、配方、编辑资源发布和测试。
- 已有 3D 原始模型和 Blender 工程可作试验输入，但过去的低精减面、程序姿势与无光照材质没有通过美术验收，不得直接批量渲染后宣布合格。

## 3. 采用的制作路线

游戏仍只运行二维精灵、序列帧及普通节点动画。角色与活动部件使用离线高质量建模、姿势和光照生成透明帧，源模型只用于制作，不进入微信包。静态图和 UI 可以精绘修整；AI 生成单体图若使用，追溯明确标为生成图，不能冒充真实三维离线渲染。

其他路线已排除：继续放大像素图不能增加造型细节；恢复实时低精 3D 会重新引入已被否决的观感；整屏静态图不能承担真实遮挡、成长与交互。优先做实际资产小样验证，再决定是否复用已有模型或重做造型。

### 统一美术规范

| 项目 | 制作及验收要求 |
| --- | --- |
| 光照 | 与参考一致的左上暖主光、柔和环境补光、温暖暗部；木梁下沿、屋檐、头发和衣褶有体积；避免大块纯色或强黑描边 |
| 角色 | 按用户补充进一步采用大头、短身、短腿的 Q 版比例，成人接近两头身，孩子头身比更大；比例以参考和实际显示对照为准，不以整体缩小替代。成人男为蓝衣短发、女为暖橘衣束发；孩子短发米色短衣；老人中性灰发、宽袍和拐杖，去除胡须及明显性别装饰 |
| 草地 | 柔和明暗斑块、细腻低对比草面、少量草簇与花石；道路边缘不规则过渡，活动区保持疏朗；不得用高频噪点或密集贴花掩盖平涂 |
| 阴影 | 物体自身明暗留在图片中，投影和接地阴影独立放在地面层；所有物体使用相同屏幕光向，避免镜像连同光照翻转和重复叠影 |
| UI | 奶油底、细暖金边、圆润立体图标、绿色和金色按钮内高光；标签仍为实时文字；面板与按钮保留九宫格，圆角和边线不随拉伸失真 |
| 视角 | 固定俯视三分之四角度，以左侧游戏画面为基准；资源保留同一相机配置。人物至少覆盖当前行走方向要求，允许复用相近视角，但不能出现倒退或工具背对目标 |

### 角色、怪物和动作

成年男、成年女、孩子、老人、婴儿共五种可见身份；孩子和老人不按性别生成重复图片，头像也共用。性别、成年条件、夫妻关系和养育业务保持原值。

动作继续以每个方向及动作 2～4 帧为目标，优先保证关键姿势：走路交替支撑、伐木抬斧与落斧、耕作工具接地、照料朝向婴儿。不能用同一张图平移或整体缩放冒充动作。换帧保持画布和足底一致，镜像不得把固定光向翻转。五类小怪和五类首领保持既有规则，按用户补充只制作正面略俯视移动帧；道路只改变其位置，不切换侧面或镜像。身体、细节及兼容配件的组合须保留清楚的材质边界，染色不能把整张脸和金属同时染脏。

用户追加要求村民脸部朝向自然：向上展示后脑与背部，左右为真实侧脸，脸、肩膀、胸口、脚尖及移动方向一致；不能身体侧走而脸始终朝镜头，也不能只转头或用镜像假造方向。离线制作保持相机与光源固定，骨骼和 IK 控制器统一转向，共用画布和地面锚点。前后脚投影的像素差异不通过逐帧居中掩盖。正式接入需同时替换现有行走及伐木/照料的镜像映射，避免新资源仍被旧规则反转。

用户再次明确：这套规格适用于全部村民，男村民只是首个验证对象。成年女村民、中性孩子、中性老人须使用同等精细度的源模型、材质、固定光照和四向动作；不能只给男村民完整方向，其余身份继续使用正面或镜像代替。所有成年角色保留大头、短身、短腿比例；孩子和老人仍各用一套中性外观。精英复用所属身份的资源，沿用已有体型与命名规则。

| 身份 | 行走候选规格 | 完整动作覆盖及验收 |
| --- | --- | --- |
| 成年男、成年女 | 每人上下左右各四帧，512×512 透明母片 | 耕作、伐木、照料与自然停姿；脸、胸口、工具朝向实际目标。四向行走完成不等于全部劳动动画完成 |
| 中性孩子 | 上下左右各四帧，同画质、较小身体与较大头身比 | 自然停姿；不增加孩子劳作业务 |
| 中性老人 | 上下左右各四帧，同画质、短步幅与持杖支撑 | 持杖静止/休息；杖独立刚性控制，不被腿部权重拉弯，手掌持续接触握点 |
| 中性婴儿 | 同等画质的躺卧轻微动作，不制作行走 | 婴儿沿用照料位置，与成人照料动作组合验收，不新增移动或其他业务状态 |

共用的是制作流程和验收质量，不是男村民的骨骼坐标。头发、衣摆、关节、拐杖各自测量并绑定；模型正面、侧面、背面均检查重建缺陷。每种身份保留完整制作源、提示词、参数、帧清单和哈希，分别记录方向检查、动作检查与最终视觉验收状态。

### 建筑与动画拆件

七类建筑继续一种一个 Laya 预制体。静态主体以完整底座图呈现，避免将小木条拼到接缝明显。三种塔执行同一质量标准：箭塔的弩臂、弓弦、箭和发射口独立；石塔投石臂、托兜和石块独立；寒塔顶部核心和发射部件独立。前栏、后栏分层，保证武器与栏杆的前后遮挡正确。三种塔均需左右朝向和射击验证，不能只精做箭塔。

参考图 1、4、8、12 级作为四个主轮廓阶段。保留现有 1～12 级逐级差异与房屋扩建规则，中间等级由同档结构和有限零件表达；不额外改升级数值。高级建筑视觉范围预先限制，足底、投影、点击区、村民工作点分别声明，不能按整张 PNG 的透明外框猜占地。

### 清晰度与包体

原画与游戏图分开保存。人物建议先试 192～256 像素帧、建筑 384～512 像素母片、图标 96～128 像素母片，再按真实设备像素密度对照。这里是小样起点，不是自动缩图指标；任何降采样都须同尺寸并排检查，不能牺牲用户指定的细节。

旧构建硬编码的 `-filter point` 和预览的 `image-rendering: pixelated` 不能用于新资源。高清链增加明确的平滑采样配置、透明边扩色和图集边缘外扩，检查黑边、白边及相邻块渗色。按钮保留完整纵向渐变，只让中间横向区段拉伸；不再把中心压缩成两像素十字。

保留 base、characters、battle 三包与现有加载重试流程。优先减重复身份、重复图、透明边和不必要帧；人物和怪物不提前放入底包。总包体和显存用实际图集估算、实测，不预先承诺与原像素包同样大小；主包不足时先重新组织资源再讨论，不静默降低画质。

## 4. 粒子移除边界

移除全部命中粒子、精英脚底粒子圈、大王之心按钮环绕粒子及相应运行模块、材质和三包声明；此前已取消的拖尾、升级粒子不恢复。

保留普通图片弹道、受击闪红、伐木树摆、建筑武器动作、婚礼红心与表情。这些不是粒子，不改变大王之心的攻速和持续时间，也不削弱精英数值。精英仍通过已有名字与体型辨识，不另加一套替代粒子。

同时移除仅供粒子消费的 `CombatPresentation.gateHits` 生产与缓存链，避免删除粒子层后事件数组持续增长；同一事件分支中的退场、死亡位置、红闪保持。混合测试文件保留这些非粒子断言，构建检查改为禁止粒子模块、材质和文件进入发布包。

1. 固定本张参考，检查现有输入，子代理审核本方案。用户已将上轮二维回退改动提交到 `a43cd35d3d9113ac55f849e599c4d3c85017adae`，以此记录基线，保留用户提交。
2. 制作男村民关键动作、三种一级塔及活动件、草地与道路边缘、一个按钮及资源图标小样。放入同一光照的小场景，输出放大细节和真实游戏尺寸，逐项对照参考；不先批量生产。三种塔全部参与，不能只验证箭塔后推定石塔、寒塔合格。
3. 小样质量得到确认后，再扩展中性孩子、老人、全部角色动作、十类敌人、七类建筑等级、树草地图和完整 UI。原图、制作源、导出参数及比较记录分类保存。
4. 接入二维图集、独立预制体和活动件；移除全部粒子依赖。重建资源白名单，验证重试仍由原流程负责，加载失败不以旧像素图或简化图替代。
5. 检查 320×568、390×844 及长屏安全区；不拉伸物体，底部操作区和标题正常，草地层次随可见范围延展。验证最大建筑等级、四塔攻击范围、屋后行走、重叠点击和战斗闭环。
6. 业务与存档文件哈希比对、适用自动测试、微信实际画面比较、包体及峰值图集内存记录，最后导出。真机结果与开发者工具结果分开记录。

美术验收须记录具体偏差及处理状态。模糊、形体不符、光照不一、脚底漂移、接缝、背景抢眼、UI 边框变形任一项未过，都不能记为“与效果图一致”。

## 7. 可行性审核后固定的实施约束

- 新 HEAD 已包含上轮二维回退改动，制作前重新记录真实基线；不还原用户提交。
- 现有模型的原始 GLB 只作为检查输入；不使用减到三千面、纹理缩成 512 的版本冒充高精源。已有程序摇摆动作须重新设计接触、支撑和重心。
- 塔底座不镜像，左右活动件独立；人物不同方向按同一屏幕光源制作。怪物按用户后续确认仅制作正面略俯视，不制作侧面、背面或镜像。地影和主体分开，光向不能随朝向反转。
- 建筑贴图像素提升不改变 128×128 逻辑画布的语义；保留 `Body`、`Weapon/attack`、`Muzzle`、`VisualBounds`、`Footprint`、`SortOrigin`、农田 `AboveGround` 与城门 `GateDoors`。多弩由同一个武器动画根驱动。
- 敌人的染色区使用显式遮罩或材质层，不沿用旧像素色阈值猜测。孩子和老人的共用映射同时覆盖地图、头像、家谱、动作及资源契约。
- 图集尺寸、外扩边、九宫格保留条带及实际解码内存随小样一起测量。源文件体积、微信包体、解码显存分开报告，不以 PNG 文件小代替运行内存检查。

本轮图片生成工具输出的单体和材质样张会明确记录生成来源，只用于造型与清晰度评审；它们不是已实现的骨骼动作，也不是 Laya 游戏运行截图。后续实际离线渲染和编辑器接入须各自提供证据。

离线透明输出与阴影分离的能力参考 Blender 官方 [渲染通道说明](https://docs.blender.org/manual/id/4.5/render/layers/passes.html)；颜色处理参考官方 [Color Management](https://docs.blender.org/manual/id/4.5/render/color_management.html)。这些文档说明能力，不代表当前素材已经达到参考图。
