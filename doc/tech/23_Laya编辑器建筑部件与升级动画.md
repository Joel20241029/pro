# Laya 编辑器建筑部件与升级动画

## 2026-11-20 固定造型与局部序列帧

现行版本使用九套固定造型，包含三种塔、城门、民居、农田、伐木场、淡紫儿之家和火堆。等级与住宅扩建继续由原系统结算，地图上的固定主体按原足点等比放大 25%。以下旧文记录的是先前的多档外观。

- 定稿母版、局部帧与拆层坐标位于 [building-motion](../../res/source/rendered2d/production/building-motion/)。母版由 `res/tools/hd2d/render-building-motion.py` 导出为静态主体和按局部有效像素裁切的统一画布。通过 `node res/tools/hd2d/author-building-motion.mjs` 登记图集配方、生成独立 Laya 预制体和导入标记。
- 原生预制体中的 `Loop:` / `Attack:` 节点声明局部序列帧。原有升级剪辑附着在活动部件，三塔序列帧由开火事件和弹道共享的战斗表现时钟推进。射口作为独立挂点，局部图像回弹不带动射口。
- 进村时仍加载建筑 ASTC。淡紫儿之家面板共用固定图标，农田水车独立排序，民居点击范围跟着放大后的静态主体计算。

日期：2026-11-12。状态：已完成七种独立预制体、108种等级/房间组合、正式游戏接入与微信导出。用户已确认 `res/design/building-upgrades/` 三张造型稿并授权实施；角度可按场景调整，主体外观须对齐设计稿。实际验证结果见第8节。

## 1. 目标与现状

2026-11-12 比例补充：用户要求民居相对人物更大。两栋民居的运行显示宽度由 116/106 调为 140/128，约增加 20%；原足底 `(108,930)` / `(222,920)` 保留，导航底座同步由 84×27 / 78×26 放大为 102×33 / 94×32。使用原 `HOUSE.lh` 部件和动画，人物尺寸保留，不新增贴图。全部等级的原生 `Footprint` 仍落在运行导航底座内；短屏与 iPhone 12 比例下检查门前通道、城墙、树木及 1/12 级屋顶，实绘见 [比例预览](../../res/preview/compact-header/README.md)。

用户要求建筑、防塔每次升级有显著变化，民居扩建应看得见；必须使用 Laya 编辑器制作可编辑的部件和动画，先试验成功再出正式图片。

改造前，`BuildingVisuals` 在完整底图上附加少量檐口、底座与徽饰，主体轮廓保持不变。现已替换为原生预制体描述的部件层级，`GameView.updateActors()` 不再重复覆盖整建筑纹理。

民居有两个不同状态：`houses` 初始 2、最多 5，表示住房数量；`housing` 表示修缮等级。现在两者分别影响房间组合与主体结构，不改变容量、价格或成长数值。

## 2. 实验路线及审核

采用 Laya 原生 2D Sprite 预制体与时间轴部件动画。先使用已有部件散图或几何占位，在编辑器内搭建、录制、保存和重新打开，导出微信后验证公开加载 API。

比较路线：整建筑序列帧需要重复保存大量相同像素；Spine 网格骨骼对刚性建筑部件并无已证明收益，还增加制作与运行库成本。本轮先用原生部件层级和 `.mc`，不把刚性部件动画称为网格蒙皮骨骼。

独立只读可行性审核已通过：本机 3.4.2 内置 `Prefab`、`AnimationClip2D`、`AnimatorClip2D` 及加载器。建议正式运行用 `AnimatorClip2D.autoPlay=false` 与公开 `gotoAndStop(normalizedTime)`，由现有表现时钟驱动；不调用私有解析、更新接口。编辑器若生成 `.mcc`，作为制作源保留。

## 3. 先做的两个样板

| 样板 | 拆分方向 | 必须看见的差异 |
| --- | --- | --- |
| 箭塔 | 塔基、支柱/塔身、楼层、平台、护栏、武器、射口挂点 | 至少三种明显主体轮廓；升级时塔身/平台拼装，攻击时武器有动作 |
| 民居 | 地基、墙体、门窗、屋顶、二层/侧翼 | 修缮改变主体；住房 2→3→5 对应新增房间或楼层，不能仅增添装饰 |

样板先证明结构和资产流程，再确定正式像素部件的尺寸、数量和预算。正式部件在不同建筑间复用，实际资源比较应包含 PNG、预制体、动作及代码增量，而不是只报告动作文件大小。

## 4. 接入约束

- 根节点保持足底与世界排序。升级动画作用于根下的结构节点，避免建筑整体漂移或压住 UI。
- 当前两栋民房在水平方向已相邻，向外扩展实体时必须核对导航；优先在既有区域内组织房间与层高，并检查城墙和村民通行。
- 武器位置随塔体变化时，以编辑器射口挂点换算弹道视觉起点；逻辑射程、伤害与敌人路线不变。
- 箭塔左右镜像沿用现有规则，文字和等级标识保持正向。
- 升级过渡沿用现有表现时间；攻击动作由真实发射事件及战斗时间驱动。暂停与倍速行为按动作用途明确，不用独立自动计时替代。
- 当前自定义 `frames.json` 不是编辑器原生图集。试验必须验证编辑器散图引用如何映射至最终图集，避免同时发布重复散图和图集。
- 微信发布的扩展名和路径遵循实际导出结果；运行白名单、分包检查及源资源台账同步更新。
- 无限升级不能无限扩大实体或累计节点；最终结构组合规则须在有限显示空间内保证相邻等级可辨识，不能继续沿用“13 级后主体冻结、仅换徽饰”的方案。

## 5. 验证顺序

1. 编辑器内创建部件层级和关键帧，实际播放；保存、关闭、重新打开后继续编辑。
2. 用编辑器导出的资源经公开 API 加载，验证微信发布及无重复图片输出。
3. 在实际游戏尺寸下对比箭塔轮廓、民居修缮及扩建；核对镜像、射口、人物遮挡、短屏边界。
4. 样板通过后制作正式部件图，保留原图、提示词、切片配方、编辑器源预制体和动作。
5. 接入其余建筑/塔，完成相关回归、微信导出和文档更新，再报告实际效果与字节变化。

## 7. 用户确认后的实施计划

### 工程和预制体

完整可编辑工程归入 `res/editor/BuildingWorkshop/`，保留 `.laya`、必要设置、类型声明、贴图 `.meta`、原生 `.mc`、`.lh` 与编辑器工具，不依赖 Downloads 中的缓存。

只维护七种独立建筑预制体：`HOUSE`、`FARM`、`LOGGING`、`GATE`、`ARROW`、`STONE`、`SLOW`，每种各一个 `.lh`。同种建筑的等级/房间组合放在自己的变体节点内；编辑时只显示所选变体，运行转换只实例化当前变体，不把所有建筑放入一个 prefab，也不在运行时创建全部隐藏等级。

### 范围、通行与遮挡

每个变体保留三个用途不同的范围：

| 范围/挂点 | 用途 |
| --- | --- |
| `VisualBounds` | 完整建筑和动画可能占用的可见范围，检查房屋互压、森林、城门血条和界面边缘 |
| `Footprint` | 地面实体占地，只包含地基/墙脚，不用屋顶矩形阻挡村民 |
| `SortOrigin` | 地面遮挡基准；升级、弹跳、屋顶增高不改变它 |
| `Muzzle` | 与武器组合对应的弹道发射点，镜像后仍从正确位置发出 |

建筑的可见大小可逐级变化，但所有实体地基严格限制在最大预留占地内。导航持续使用这块预留占地，升级时不会把已经行走的村民困在新墙体里，也不因换级突然改变路线。范围以隐藏的命名节点及其位置/尺寸保存在编辑器中，可选中检查；没有额外绘制到游戏中的调试边框。转换器检查结构、属性与引用，建筑测试检查范围越界。塔基预留宽度由70微调为72设计像素以完整容纳高级基座；这不是用大屋顶矩形阻挡人物。

世界遮挡继续按足底排序，同一建筑的部件在独立排序根内一起绘制。农田田畦是可行走地面；水车是单独的遮挡组，使用自身足底参与排序。水车基座在128源画布中的范围为 `(91,85,26,8)`，开村起固定预留，升级时不改变导航。水车放在农田右侧，与城墙留出距离；田畦其他部分仍可耕作。门廊不新增穿过墙体的通道。

### 造型和验证顺序

1. 归档被否定的方石楼试稿，按照已确认的暖木箭塔、圆石投石塔、亭式寒塔和宽坡屋顶重做部件；先完成箭塔和民居实际组装对照。
2. 在真实 Laya 编辑器里保存七种独立 prefab、切换变体、播放两段原生动画并重新打开；共用图集与动画，避免复制完整升级图片。
3. 完成布局转换与范围校验；运行层只加载当前变体。旧整图只在仍使用的图标/面板保留，弃用升级饰件退出图集并保留源文件。
4. 在短屏/长屏检查全部建筑最大造型、两个方向的塔、房间 2/3/4/5、城门血条、村民前后穿行、农田立体部件，以及暂停/倍速。
5. 更新所有相关说明、资源台账、构建白名单和独立工程入口；运行测试并导出微信包，记录实际大小，不以设计稿冒充引擎效果。

以上范围约束是表现与导航实现选择，不新增业务兜底；不改生产、伤害、射程、人口、存档或奖励规则。

### 编辑器源与资源链路

- 原始工程：`res/editor/BuildingWorkshop/BuildingWorkshop.laya`，使用LayaAir IDE 3.4.2。
- 原生文件：`assets/buildingAuthoring/prefabs/`、`animations/`及`textures/`。已实际在IDE中生成、打开并查看ARROW层级，原生序列化保存七个文件，共108个变体。
- 原生动作：upgrade.mc为0.6秒部件组装，attack.mc为0.3秒武器动作。它们来自Laya时间轴；运行使用公开的`AnimatorClip2D.gotoAndStop`，没有私有二进制解析器。升级/攻击分别遵守表现时钟和战斗时钟。
- 运行数据：`res/native/buildings.json`及两个`.mc`。转换器拒绝未知节点属性、变换后的根容器、异常范围节点、重复节点名及未声明纹理/动画。
- 发射口在Weapon内部，经过层级缩放和左右镜像换算。已经发出的弹道保存相对塔位偏移，屏幕重排时跟随当前塔位，后续武器回弹不会拉动已发射箭石。
- 农田水车退出地面绘制组，独立参与深度排序；重建、缩放与销毁都纳入验证。
- `structures_v2`分格时按主体连通区域确定明确的`sourceCropWithinCell`，避免相邻格的屋檐碎片误入部件；不会把低透明像素裁边阈值当作运行图集的裁边规则。
- 运行图集仍仅去掉alpha=0的透明外圈，源画布偏移与动画脚底通过frames.json恢复。10张弃用升级挂饰和旧投石机关退出运行白名单，源图归档保留。

编辑器中间缓存、测试编译与日志放在Downloads；正式设计稿、母版、编辑器源、脚本、分类散图和实绘结果保存在res的对应目录，并附README。`res/README.md`是入口索引。
