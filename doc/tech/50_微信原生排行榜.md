# 微信原生排行榜

## 目标与范围

本轮版本 `1.0.28` ，用微信原生 `screenCanvas` 直接显示好友守村榜，去掉 Laya 的 `OpenDataContextView`、共享画布纹理与逐帧上传链路。沿用官方开放域 Layout 模板、云成绩取最高值、朋友与隐私授权规则；外层绿色面板、标题、关闭按钮和游戏暂停继续使用现有界面。

用户已确认：基础库低于 `3.6.6` 或缺少原生显示能力时提示“请升级微信后使用排行榜”，其他游戏照常运行，最高纪录仍保存在本地，不回退 Laya 显示。初始化异常沿用关闭重开方式，不增加自动重试。

## 依据与初始化顺序

- 微信官方 [getOpenDataContext](https://developers.weixin.qq.com/minigame/dev/api/open-api/context/wx.getOpenDataContext.html) 提供 `sharedCanvasMode: "screenCanvas"` ，画布独立上屏。
- 微信官方 [开放数据域](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/open-data.html) 说明原生模式的基础库门槛、CSS 定位与单例模式限制。
- 初版候选在主场景打开榜单时才选择原生模式，IDE 仍然空白；同包只将初始化提前到 `weapp-adapter.js` 前，真实榜单显示。该对照证明本工程需要提前初始化，不将它宣称为旧正式版空白的最终根因。
- `WechatBuild.onCreateManifest` 在引擎生成入口之后、打包之前添加启动段：明确原生模式并将画布缩成屏外 `1px` ，随后执行原入口。保留原适配器、引擎库、分包和业务入口，不修改引擎文件。
- 运行端与导出启动段共用 `RankingConfig` 的 SDK 比较函数和配置。若未来引擎入口模板不符，导出直接报错，避免静默插入到错误位置。

## 生命周期与数据边界

`WechatRankingCanvas` 持有单例上下文，榜单固定为 `600×680` 像素，只在准备时设置一次；后续调整 CSS 显示矩形，不反复清空画布。`RankingView` 只做空白布局占位，不创建 Laya 纹理。它使用已有窗口变换计算原生画布与 Layout 触摸区域，不重复乘 DPR 或安全区偏移。

同一时刻只有当前请求拥有画布。旧授权回调、旧面板移动或销毁不能操作后来打开的榜单；部分 CSS 写入失败也会清理已经露出的画布。关闭及切后台隐藏原生画布，原面板暂停/恢复流程不变，回前台点击继续后重新请求榜单。

开放域 `index.js`、`score-store.js`、`render.js`、`engine.js` 保持原内容；好友头像、昵称和云成绩继续留在开放域，不增加主域读取、服务器或日志中的好友身份字段。本轮不新增图片、音频或分包。

## 后台日志

沿用微信官方游戏日志，公共字段 `version=1.0.28`、`build=1.0.28-c2a2525a1a00`、`render=screenCanvas`。查询步骤沿用 [正式版排行榜诊断](49_正式版排行榜诊断.md)。

新增 `native_canvas_ready`、`native_show`、`native_hide`；`render_sample` 记录 CSS 位置、尺寸、拥有状态和节点是否在舞台中。移除旧的纹理创建、上传计数事件。`message_returned` 仍只表示主域消息调用返回；样式正确也不等于真实屏幕已经显示。

隐私面板由微信决定是否需要再次授权，不强制重复弹出。`privacy_snapshot.needAuthorization=false` 本身不能确定所有朋友信息权限已具备，仍执行原授权链路。

### 1.0.94 初始化失败原因

微信开放域指南将 `screenCanvas` 定义为原生上屏的全局单例。构建入口在微信主画布创建后、适配器修改画布原型前获取一次上下文，同时设置榜单逻辑分辨率并保存原生 `style`。主域后续用同一对象发送成绩及开关面板消息，开放域用 `wx.getSharedCanvas()` 的 2D 上下文绘制好友数据。榜单打开时，`native_canvas_ready.styleRetainedAfterAdapter` 记录适配器加载后画布仍能否读到同一个样式对象。 [微信开放数据域指南](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/opendata/basic.html#screenCanvas-%E6%A8%A1%E5%BC%8F)

`view_error` 和 `message_error` 在原生画布能力检查失败时带上 `nativeCanvasFailure`。字段只包含固定原因，继续使用 `ranking` 标签、原请求标识、去重和日志限额。

| `nativeCanvasFailure` | 失败检查 |
| --- | --- |
| `sdk_version_missing` | 运行时没有读到基础库版本 |
| `sdk_version_rejected` | 基础库版本格式无法识别 |
| `sdk_below_minimum` | 基础库版本低于 `3.6.6`，面板提示升级微信 |
| `open_data_api_missing` | `wx.getOpenDataContext` 不可调用 |
| `canvas_missing` | 开放数据域上下文缺少画布 |
| `canvas_style_missing` | 画布缺少原生上屏所需的 `style` |
| `canvas_is_main` | 开放域返回了主画布，启动流程保留主画布原样 |
| `startup_hook_unavailable` | 启动入口未能在创建主画布时执行捕获 |
| `startup_capture_error` | 启动时获取原生上屏对象或设置其属性抛出异常 |

用同一手机和微信账号分别打开体验版和正式版排行榜。在后台查 `ranking`，先按 `env=trial`、`env=release` 核对各自的 `build`、`wechatVersion` 和 `sdkVersion`，再顺着同一个 `request` 查 `nativeCanvasFailure`、`native_canvas_ready` 与 `native_show`。诊断版须在对应渠道运行，旧线上包不会补报新字段。游戏日志接口不可用时，同一事件仍输出到本地控制台。
