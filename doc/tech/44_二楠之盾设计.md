# 二楠之盾：城门短时无敌

日期：2026-11-15。状态：已按用户确认方案完成实施、自动回归及微信IDE验证，微信平台确认1.0.22上传成功并覆盖体验版。构建标识：`1.0.22-b6a7dc75725e`。

## 用户要求与确认边界

名称确定为“二楠之盾”，效果是城门一段时间无敌。用户先确认显示效果设计，再明确回复“可以执行吧”，授权实施、测试并上传体验版。

确认的首版规则如下：

| 项目 | 确认规则 |
| --- | --- |
| 保护对象 | 城门；普通怪与首领的触门伤害均免疫 |
| 时长 | 8个战斗秒；3倍速约2.7个现实秒，暂停冻结 |
| 使用 | 每夜一次，免费施放；与现有两种战技三选一携带 |
| 学习资格 | 当前村庄成功守住5波 |
| 一次费用 | 60木材＋30粮食；学会后免费切换与使用 |
| 保留规则 | 白天学习/换技、传承保留已学会、纯净重开恢复初始战技 |
| 排除效果 | 不回血、不反伤、不击退、不改变塔伤害/攻速，不新增击杀奖励 |

5波与60木30粮相对“百毅靓之怒”的3波、40木20粮向后安排一个学习档位；8秒为用户确认的首版值。当前怪物到门后退场，护盾可以消化保护期内集中到门的高血首领，因此不能仅因8秒短于攻击技能15秒，就认为更弱。同波次对照结果见验收记录；如后续建议改动数值，需另向用户说明依据。

## 表现方案

推荐青蓝透明护盾配少量金边，区别于百毅靓之怒的红白旋刃；沿用当前高清预渲染二维的建筑与明亮田园UI。

| 阶段 | 显示 |
| --- | --- |
| 发动 | 约0.3战斗秒，光弧从门脚展开，形成包住城门的透明拱形罩；盾形徽记短暂点亮 |
| 持续 | 青蓝亮边、低透明内面、贴地椭圆边缘；缓慢呼吸和一次简单扫光，木门与屋顶仍清楚 |
| 抵挡 | 实际触门时，护盾前方出现局部青白涟漪；不表现为敌人反弹、爆炸或额外伤害 |
| 自然结束 | 约0.25战斗秒，轮廓变细并收拢淡出，不碎裂、不产生粒子 |
| 战斗结束 | 按既有结算立即收起，不为播放动画延迟胜利、失败或存档 |

城门真实HP数字与血条比例保留；保护期间血条临时青蓝，旁边增加紧凑盾标记。不得增加一整行城门文字、挡住已有数值或塔名。顶部已有状态条显示“二楠之盾 · 城门无敌 · 还剩X秒”。底部原圆形按钮保持金色底板，替换青蓝金边盾牌图标，显示完整四字名称和既有倒计时；已用状态仍由原按钮流程管理。

比较过三种表达：纯城门染色辨识度不足；大块实体盾牌容易盖住木质城门；透明拱罩配清楚边缘更适合当前小屏场景。因此本稿提出第三种，用户仍可调整。效果稿只用于确认美术方向，不能直接切图作为正式可用素材。

## 已核对的现有实现

- `TacticConfig.ts` 已登记两种攻击战技，尚无城门保护类型；新增效果需要扩展类型及配置校验。护盾没有倍率语义，不能填一个虚假的攻速或伤害倍率。
- `Tactics.ts` 与 `TacticPanels.ts` 已统一学习条件、木粮原子扣费、列表排序、详情和携带；可增加第三条配置复用，最短屏需检查三条卡片的滚动。
- `BattleSimulation.step()` 先生成/召唤，再移动怪物；到门后扣耐久、将怪物hp置0、发gate事件并移除，之后判断失败和塔攻击。建议只在有效期内跳过扣耐久，保留其余顺序。
- `GameHud.update()` 目前把非伤害技能按攻速显示，新盾必须有明确状态文案分支；`NightControls` 已按战技读取图标、名称、持续时间，无需新建夜间操作面板。
- `CombatPresentation` 将触门怪物标为退场并清理死亡/红闪，避免在途弹道残留。新的抵挡事件必须继续执行这条清理路径。
- `GameSession` 最后一只怪退场时立即结算，清空战斗和表现事件；最后一次抵挡不保证涟漪完整播放，这是沿用当前结算优先规则。

## 最小接入计划

1. 用户确认效果和规则后，新增明确的城门无敌效果及二楠之盾配置；学习、切换、一次施放与战前快照复用现有系统，不增加存档迁移或默认兜底。
2. 到门判定记录当步是否被盾抵挡，以及逻辑tick和逻辑撞击位置；表现层不能用后续剩余时间反推旧事件。剩余1tick时，该步所有触门怪物均受保护，步末统一减时。
3. 城门护盾使用独立场景节点按门前/门后排序，不进入建筑子树和pickDepth；边界随实际城门外观与布局挂点计算，不改变建筑占地、点击区域或人物遮挡。
4. 用固定少量涟漪节点承接触门反馈，按战斗时钟推进；暂停冻结、倍速同步。3倍速追帧的首个可见反馈可从首次观察起算短闪，但不延长真实免伤时间。
5. 单独制作透明素材，计划1张基础包技能图标、2～3张战斗包共享特效贴图。原图、生成记录、采样/裁切配方、图集和文档同步；实际包体制作后检查，不承诺未经测量的字节数。
6. 完成自动回归、平衡对照与微信IDE实绘，清理开发存档但保留排行榜记录；通过后重新导出并上传下一体验版，默认接续为1.0.22，填写简短更新描述。

## 实际实现与制作记录

- `TacticConfig`采用区分效果的联合类型，护盾不携带虚假攻击倍率。复用现有学习扣费、携带、战前快照、传承与纯净重开规则。
- `BattleSimulation`只在有效保护时跳过触门扣血，仍退场并发出含`blocked/tick/x/y`的gate快照；其他攻击伤害、攻速、召唤顺序及结算不变。
- `GateShieldEffects`持有两个独立排序根、护罩、扫光、发动徽记及三个固定涟漪，不进入建筑子树或人物点选列表。使用实际Body范围和战斗tick，无粒子、无逐帧新增资源。
- IDE中确认Laya 3.4的`Sprite.texture`绘制命令不会随后续尺寸改动同步重建；新效果统一显式`graphics.drawImage`尺寸，避免升级换档和涟漪放大时仍绘制旧大小。
- 护罩底部按母画布92.5%的亮弧位置对齐门脚。长屏血条整体上提22逻辑像素；战场低于600逻辑像素时使用略扁的护罩和18号血量字，保留原血条高度。盾标记放在数字右侧，避免遮住左侧塔名。
- 新增一个96×96基础包图标，以及256×192护罩、256×80贴地环、96×96涟漪三张战斗包贴图。原349项配方不变；正式资源353项、48组动画、13页图集。源图、生成提示词、连续alpha清理与裁切配方见 [制作源](../../res/source/effects/tactic-shield/README.md)。
