## 已确认要求与设计建议

用户已经明确的要求：

- 微信小游戏，竖屏，轻量。
- 村落经营、人类村民成家繁衍、塔防结合。
- 单机游戏。
- 保持轻量；2026-11-11 用户明确启用微信原生分包，完整内容仍按 3,500,000 字节内部预算检查。
- 能够持续游玩，没有固定的预制关卡终点。
- 人物采用序列帧动画，每个动作 2～4 帧；当前照料及老人每组 2 帧，其余每组 4 帧。
- 成人男女各一种外观，劳作期内均能承担所有岗位；自动按专长优先补空岗，玩家可调岗。
- 普通劳作期后留村养老 3 个成功守夜夜晚；精英为劳作 18 夜、养老 5 夜，普通每夜 2 粮、节俭 1 粮，占住房；寿终才进入家谱。
- 九类分页列表改为上下滑动，关闭按钮在右侧，去除左上麦穗和地图独立“家园”标签。
- 四辈儿（男）、芊芊（女）进入孩子和旅人随机姓名库，不新增人口。
- 不兼容旧版本存档，开发交付时人工清本游戏双槽；正常同版本重启保留进度。

2026-11-11 包体要求更新：用户明确要求处理分包，采用主包加一个 `resources/village` 微信原生资源包。主包保留引擎、适配、代码、启动场景与开放数据域；村庄图集和动画配置加载完成后才进入游戏。分包由微信分发，不接入远程资源服务器或共享引擎插件；首次下载资源包需要网络。完整方案与验证边界见 [11 微信原生分包](../tech/11_微信原生分包.md)。早期设计的“严格单包”约束由本次确认替代。

早期建议与实际首版收敛处，以 [04 首版实现与运行](../tech/04_首版实现与运行.md) 和 [08 晚年生活与滑动列表](../tech/08_晚年生活与滑动列表.md) 为准。功能已获用户授权并实施，不代表完成数值调平或上线验收。
