# 塔部件与道路候选

这里保存高清二维小场景使用的原始图片、裁切配方和生成提示词。所有 PNG 均为 AI 生成的二维候选，不冒充 Blender 渲染输出。

| 文件 | 用途 |
| --- | --- |
| `arrow_parts.png` | 箭塔完整主体、独立前栏和活动弩；分别导入后检查前后层次 |
| `stone_parts.png` | 石塔固定主体、装石托兜和空托兜；当前小场景只检查装石组合 |
| `frost_parts.png` | 寒塔主体与独立顶部核心 |
| `road_sprite.png` | 按用户允许的独立图片方案制作的圆弯道路，带透明通道 |
| `road_material.png` | 前一轮程序道路的材质试验输入，保留溯源；当前场景不使用 |
| `sources.json`、`road-source.json` | 完整提示词、参考及生成来源 |
| `probe-recipe.json` | 原图裁切范围、输出高度与制作工程目标路径，可重复构建 |
| `road-coverage.json` | 既有逻辑道路的 505 个采样点与道路图片透明度覆盖检查，未改变寻路点 |

执行 `node res/tools/hd2d/build-probe-assets.mjs` 生成编辑器使用的派生图；只裁透明边、平滑缩图，不重绘。原图保持不变。

当前三种塔各有独立 `.lh`，暂共用原生旋转片段验证“武器能动、主体不动”。这不等于三种塔的最终攻击动作：石塔托兜的连接、寒塔核心的动作及左右朝向还需要分别完成。范围框只是小场景占位，不能用于正式村民导航。

道路覆盖通过仅证明原有逻辑点落在路面内，不证明怪物全身、战斗碰撞、路边装饰和所有屏幕比例已验收。
