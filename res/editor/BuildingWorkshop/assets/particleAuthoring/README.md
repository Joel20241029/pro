# 原生 2D 粒子制作源

LayaAir IDE 3.4.2 使用此目录维护 6 个独立粒子效果。1.0.13 已移除攻击拖尾与建筑升级粒子，保留 4 种命中、精英脚底圈和红色按钮环绕。制作源保留在 `res`，不会将整个编辑器工程带进微信包。

| 目录或文件 | 用途 |
| --- | --- |
| `prefabs/` | 一种效果一个原生 `.lh`，直接在属性面板调整发射、形状、颜色和尺寸曲线 |
| `materials/` | 共享粒子材质，透明混合、关闭深度写入，复用引擎内置 1×1 白纹理 |
| `shaders/` | 从本项目 3.4.2 原生 Particle2D shader 保留的 VillageParticle shader；使用粒子模块注册的 include |
| `recipe.json` | 首次搭建参数和包归属，尺寸为 720 逻辑画布像素，寿命为秒，rate 为每秒数量 |

## 编辑与重建

1. 打开 `BuildingWorkshop.laya`，在 `prefabs/` 编辑目标效果，保存 `.lh` 与 `.meta`。
2. `工具 / BuildVillageParticles` 用 recipe 重建全部原生预制体和共享材质，会覆盖手工调参。只在明确重做时使用；修改配方后必须实际执行此菜单，不能仅手改发布 JSON。
3. 在仓库根执行 `node res/tools/build-resources.mjs --work <Downloads内工作目录> --sync`。转换器读取已保存的原生预制体，核验材质 UUID 和白纹理引用，再按包生成 `particles.json`。
4. 完成正式游戏的 CommonJS 测试编译后，执行 `工具 / VerifyParticlesInGame`。入口读取 `~/Downloads/daidai-release-1.0.13/checks/compiled/`，输出 `checks/native/`；使用内存存档，不连接微信账号。
5. 正式微信导出后运行 `check-wechat-package.mjs`，核对粒子模块加载顺序、源/包内容、分包边界及字节预算。

## 固定约束

- `playOnAwake=false`，运行时由所属对象明确播放、暂停和回收。
- 命中粒子只发一批；非循环发射窗口保持 1 秒，避免 3 倍速低帧率首帧越过过短 duration 而漏掉 burst。命中寿命为 0.24～0.43 秒。
- startSize 两轴模式保持一致；尺寸生命周期两轴都设置曲线。不得用默认 Y 模式覆盖 X 模式。
- 每系统最多 32 粒，均使用局部模拟空间；同一份视觉种子 137 不参与游戏随机流。命中根节点固定在命中位置，精英圈随人物移动，按钮根节点随按压移动。
- 精英用半径 20、Y 比例 0.35 的椭圆边缘持续发射，保留间隙。按钮由代码沿圆角边缘移动发射点。
- 按钮采用鲜红色 `#f04435`，最大初始尺寸 7 逻辑像素、最小为其 60%，每秒 40 粒、寿命 0.65 秒；最多约 26 粒同时存在，避免与金色底板混色。这些是用户要求加强可用提示的表现参数，修改只影响醒目程度与绘制量，不影响技能判定。
- 不额外创建 PNG；白纹理、材质和 shader 仅底包持有。人物包只包含精英配置，守夜包只包含攻击与撞门配置。
